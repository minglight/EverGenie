# 模組：board（`internal/base/app/board`）
Status: DRAFT — 設計 2026-10-23（P0-S7，原 `web` 卡）；2026-11-01 `internal/web` 拆掉後改成這張卡；2026-11-02 瘦身（各期實作對照、演變過程拿掉），pending author review.

**目的：** 看板：Go 這一端是外殼（聽連接埠、送內嵌的畫面檔、把 `/api/` 的請求轉給核心、頭像與分享檔、上傳、套件頁面的編譯與公開檔案）；前端 `web/apps/board` 的畫面規則（WEB-n）也記在這張卡。
**種類：** 底層模組（`internal/base/app` 的子套件，法律第 8 條；沒有自己的 sdk 服務、不實作 `Routes()`；有一項健檢 `Checks()`：`config.web_cross_site`）

> **檔案**：`module.go`（`Module`：`Start`／`Stop`／`Handler`／`Addr`）、`server.go`（路由、身分覆寫、白名單、頭像、分享檔、靜態檔）、`cors.go`（跨站與 Host 檢查，WEB-78）、`upload.go`、`appicon.go`（WEB-77）、`assets.go`＋`bundle.go`＋`pkgfiles.go`（`Assets`：套件頁面編譯與快取、公開檔案、頭像解析、`VideoURL`）、`embed.go`＋`dist/`。前端 `web/apps/board/src/`（`shell/`、`pages/<職位>/`、`components/`、`data/`、`lib/`、`pkg/`、`i18n/zh-TW.ts`），共用元件 `web/packages/ui/`。
> sdk `web` 服務的方法各由業務模組用 `Mount.Methods` 登記（網址不變）：`get_menu`、`get_pages`、`get_menu_prefs`、`set_menu_prefs` → 業務模組 `menu`（`internal/feature/inbox/menu`，選單的規則 WEB-2、3、15、65 的伺服器那一半在那張卡）；`get_overview` → `overview`；`get_roster`、`get_agents` → `agents`（AGS-6）；`get_health` → `doctor`（DCT-9）；`get_trust` → `trust`；`get_sites`、`set_sites`、`set_allow_boards`、`set_owner_login` → `settings`（SET-8）；`get_boot_prompts`、`answer_boot_prompt` → `chat`（CHT-1）。看板不經 unix socket 打自己：資料由各業務模組在行程內提供。

### 伺服器（`server.go`、`cors.go`、`upload.go`）
- **監聽**：`Start` 在 `api` 之後，只聽 `127.0.0.1:<web.port>`（HTTPS 由 `evergenie tailscale setup` 掛到 Tailscale 服務 `svc:genie[-dev]-<owner>-<machine>`，D-43）；沒有家不聽；port 被占用回 `unavailable`「看板的連接埠 <n> 已被占用，請改 home.toml 的 web.port」。最外層不用 `http.ServeMux`（它會把含 `..` 的路徑轉址），自己依前綴分流。
- **看板的請求一律算主人**（`forceIdentity`）：`/api/*` 的 JSON body 的 `by` 一律換成 `{"name": "owner(web)"}`（沒有也補上；例外 `vault.changes` 的 `by` 是篩選字串）。`bus.send` 另把 `from` 換成 `owner(web)`、只准 `kind: chat`（缺了補 `chat`，其他回 `forbidden`「看板只能送聊天訊息」）。
- **白名單**（`allowedAPI` 是單一正本）：`web` 全部；`session`、`notify`、`tasks`、`reminders`、`goals`（list、get、withdraw、create）、`policy`（list、get、decide、revoke）、`bus`（send、get、subscribe，topics 限 `boardTopics`，WEB-72）、`rules`、`vault`（另見下一條）、`package`（不含 `hello`）、`agents`（set_field、set_account、assign、knowledge、set_knowledge）、`personas`、`system`、`scheduler` 各列一組方法；不開放的有 `policy.request`、`goals.propose`／`update_planbook`／`done`、`notify.nudge`、`engine`、`engine_host`。其他回 404 `not_found`「看板不提供這個服務」、不轉給 `api`。轉送用 `Deps.API.Handler()`（行程內）。`personas.pack_sync`（衣櫃與展示間的「現在再試」，DEV-157）由身分覆寫拿掉 `pointer` 與 `force`（大小寫不同的寫法也算）：一律用服務自己的角色包指標、不蓋掉主人改過的（`agents.md` PRS-28）。測試 `TestBoardAllowsSettingsServices`、`TestBoardAllowsGoalCreate`、`TestBoardAllowsPersonas`。
- **vault 只限套件資料**（`vaultPackageOnly`）：`kind`（`put` 看 `record.kind`）要含 `.`；核心種類、沒帶種類、`watch`、`append` 回 404；例外 `changes`（只讀）與夜班清單（`note`、`system/night-queue`）的 `get`、`put`。`system.backups` 帶 `apply: true` 403「看板不能刪備份；要清理，跟任何一位秘書說「幫我清理舊的設定備份」」。測試 `TestBoardVaultExceptions`。
- **跨站與 Host**（WEB-78）：
  - 同源＝沒有 `Origin`，或 `Origin` 只有一個、是 `scheme://host[:port]` 而且等於 `web.public_url`，或等於請求的 `Host` 而 `Host` 是 loopback 或 `*.ts.net`（只認 https）；任意網域的 `Host` 不算（擋 DNS rebinding）。同源不查身分、不帶 CORS 標頭。

## 已知限制
- 「這台 Mac 本機」的判斷（WEB-187）擋不了兩種：這台 Mac 上的別的程式直接打 `127.0.0.1`（跟 D-24 同一個限制，它本來就能自己跑 `tailscale`）；有人另外架了不帶轉送標頭的通道（例：`ssh -L` 把看板的埠轉到別台）——那個人已經能登入這台 Mac。Tailscale 整條 TCP 直接轉送（`tailscale serve --tcp`／`funnel --tcp` 這類不經 HTTP 代理、不補標頭的掛法）進來的請求看起來跟本機一樣，偵測不到也擋不了；EverGenie 自己只用 HTTPS 代理的掛法（SET-11），主人另外這樣掛等於自己把看板的埠交出去。看板沒有登入（作者 2026-11-16 定：不做），Funnel 開著時公網上任何人都能用看板，所以只警告並給關掉的按鈕，不替主人擋。
- 看板只聽 `127.0.0.1`；loopback 上任何本機程式都打得到，跟 `api` 的 unix socket 一樣沒有身分驗證（D-24），也能偽造 `Origin` 與 `Tailscale-User-Login`。CORS 防的是別的網站在主人瀏覽器裡偷打，真正的界線是 tailnet ACL。
- 別台看板的身分只信 `Tailscale-User-Login`（Tailscale 服務轉進來時補上；tag 身分的機器沒有，別台一律拒絕，這是設計；從這台自己的瀏覽器連回這台要開 `web.trust_self`，WEB-130）。Funnel 不帶身分標頭、跨站一定被擋；開了 Funnel 的話不帶 Origin 的請求會對公網開放。
- 身分檢查（`gateCrossSite`）只擋得住瀏覽器，因為 `Origin` 瀏覽器不能偽造；tailnet 上能連到這台的非瀏覽器程式（含 tag 機器）送 `Origin: <本台 public_url>` 就是同源、不查身分（`sameOrigin`），真正的界線是 tailnet ACL。
- `web.trust_self` 開著時（WEB-130）：這台機器上任何瀏覽器、任何 OS 帳號、容器只要經 Tailscale serve 連進來、頁面的 Origin 在 `allow_boards`，就等於主人（以前要主人裝置的登入）——跟 D-24 同級，是為了讓這台自己的瀏覽器看別台看板而做的設計選擇。安全性靠「請求一定經過 Tailscale serve、serve 會覆寫 `X-Forwarded-For`」（實測；舊版 Tailscale 若改成附加，`偽造值, 真實值` 會被「沒有逗號」擋下）；這台上若有別的反向代理、tunnel 原樣轉送用戶端的 `X-Forwarded-For`，這個判斷就不可信（它們本來也能偽造 `Tailscale-User-Login`）。Funnel 的來源不會等於這台自己的位址，且帶 `Tailscale-Funnel-Request` 的一律不算（推論加縱深防禦，沒實測）。
- 放進 `allow_boards` 的那台網域上任何程式都能操作這台；它改不了 `allow_boards`、`owner_login`（WEB-79），但能用 `bus.send` 叫秘書跑 CLI 改。清單只放自己的家。`*.ts.net` 的 Host 不比對是不是這台自己的服務名。
- 套件頁面只在 `GetPages`／`GetMenu` 時依指紋重編，沒有熱更新、沒有 CSS／圖檔 loader；`packages/mine/` 的頁面只能用看板建置時已經有的 Tailwind class。
- 選單編輯器不能挑自訂選單元件；Goal 的篩選與標籤沒做；紀錄的「誰」篩不出「系統」；權限頁的信任清單唯讀（改權限走 WEB-22）；角色庫沒有刪除、改代號，也不能編輯被官方蓋住的我的卡。
- 影片一律靜音；iOS 加入主畫面、真的推播送達與點開深連結沒在真機驗（e2e 連不到推播服務）；FEN-21 的 `pagehide` 只驗了換路由。
- Goal 聊天（WEB-82）：兩個分頁同時第一次開，第一句會送兩次（先問再開，不是原子的）。

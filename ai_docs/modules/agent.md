# 模組：agent（`internal/base/agent`）
Status: DRAFT — 設計 2026-10-23（P0-S7）；2026-10-24 加 AGT-13（P3 放行）；2026-10-26 加角色庫與說話層強度（AGT-20、AGT-21，P6-5a、D-31）。

**目的：** 秘書名冊：職位、人設綁定、大腦／分身、記憶與日誌、組裝給 session 的指令；角色庫（人設卡的管理）與說話層強度。取代舊的 `render` 與 SessionStart 注入。
**種類：** 底層模組（`internal/base/`；沒有 HTTP、沒有指令，只給別人呼叫）

欄位與路徑見 `schemas/agent.md`、`schemas/persona.md`。**角色庫的程式（AGT-20、21、23、24、31、32）2026-11-01 起在業務模組 `internal/feature/agents/persona`**（[agents.md](agents.md) 的 persona 段），規則留在這張卡；名冊只經 `PersonaSource` 讀卡。測試沒寫路徑的：名冊在 `internal/base/agent/`、角色庫在 `internal/feature/agents/persona/`。

## MUST
### 名冊
- **AGT-1** — 名冊是職位 id、職責、現任人設（人名）、以前的人名的唯一正本（`vault/agents/<id>/agent.md`）；同一個職位 id 別處沒有設定。測試 `TestRosterSingleSource`。
- **AGT-2** — 檔案、紀錄、事件一律寫職位 id；只有對使用者說的話與畫面用人名；使用者用以前的人名時依 `former_names` 對照回職位 id，回答用現任人名（`Resolve("雅典娜")`、`"Athena"`、`"code"` 都得 `code`）。`PersonaName` 每次讀現任人設的 name、不快取。測試 `TestResolveAliasesAndFormerNames`、`TestPersonaNameReadsCurrentBinding`。
- **AGT-3** — 換人設只改 `persona` 欄位；`memory.md`、`journal/`、`addendum.md` 的內容與修改時間都不變。測試 `TestPatchAgentKeepsMemory`。
- **AGT-4** — 一個人設可以同時擔任多個職位；`shares_conversation_with` 讓多個職位共用同一個對話（代管），循環被拒（`Start` 時再驗一次）。測試 `TestSharedConversationNoCycle`、`TestStartRejectsSharedCycle`。
- **AGT-18** — 名冊管理（`Create`／`Archive`／`Rename`／`Assign`／`Swap`／`SetAccount`／`SetField`／`AddRule`／`Customizations`／`Cards`）的規則在業務塊 `agents`（`internal/feature/agents/roster/manage.go`，[agents.md](agents.md) AGS-8）。名冊只給單筆紀錄的基本操作（`records.go`）：`Record`（含封存的）、`Records`（一位秘書名下沒封存的 `agent`、`addendum`、`memory`、`note`、`journal`、`changelog`）、`PutAgent`、`PatchAgent`、`SetBody`、`ArchiveRecord`、`MoveRecord`、`Changed`（發 `agent.changed`）、`Persona`／`LivePersona`；只碰 agent 擁有的種類，別的回 `invalid`；不判斷誰能做、id 格式、白名單。秘書名下的排程（`job`）不經名冊：擁有者是 tasks 塊，agents 塊經自己的 `Deps.Jobs` 叫 tasks 塊的 job。測試 `records_test.go` → `TestRecordOpsOnlyOwnedKinds`、`TestRecordsListsOwnBelongings`。
- **AGT-19** — 附加規則與給引擎的卡片內文（`AddRule`、`Cards`）也在業務塊 `agents`（AGS-8）；名冊守 AGT-N3 與 `WriteDuties` 不動 `addendum`。測試 `TestAddendumSurvivesOfficialUpdate`。

### 記憶、日誌、職責
- **AGT-6** — 每位秘書有長期記憶 `memory.md` 與日誌；日誌只能追加，覆寫既有行被拒。`WriteMemory` 只有本人或 `system`。測試 `TestJournalAppendOnly`、`TestMemoryPerAgent`。
- **AGT-7** — 使用者 profile（`vault/profile.md`）已退休（DEV-161）：開場不帶、核心不再讀，內容由 AGT-40 搬進主題「主人」；`WriteProfile` 留著、仍只有 `life` 能寫（`by: code` 失敗）。測試 `TestProfileOnlyLife`。
- **AGT-39** — 主題筆記（DEV-161，`notes.go`，規格 `schemas/note.md`）：種類 `topic`（`vault/notes/<分類>/<主題>.md`）與 `topic_category`（`vault/notes/<分類>/<分類>.md`）由本模組登記規格；寫入只有 `AddNote`、`SetNote`、`ArchiveNote`、`AddNoteCategory`（sdk `notes` 服務，業務塊 `agents/notes` 轉進來）。寫的人：主人（行尾標「主人」，`set` 不檢查標記）、`system`、名冊上的職位；其他 `forbidden`。`AddNote` 行尾一律標「（<寫的人> MM-DD）」（家的時區；送進來的標記換掉，不能冒名）；新主題要分類（「主人」除外）與一句說明、分類要先有、`follow` 預設寫的人；名字或別名找主題，別名對到兩份回 `conflict`。`SetNote` 整份取代：改內文要帶 `Revision`（`notes show` 的版本），沒帶回 `invalid`、跟目前版本不同回 `conflict`（別人剛改過，不蓋掉對方的行），只改檔頭（`KeepBody`）不用帶；內文不能有檔頭；新出現、沒標記或標成別人的行回 `invalid` 並列行號（原本就在的不算）。`Start` 補缺的官方預設分類（`DefaultCategories`，只建缺的、封存的不算缺；說明檔壞掉只記一行警告、不擋啟動；說明檔帶各分類的建議段落，只是建議、不驗證，`notes categories list` 有就多印一行；說明卡的建議段落表跟它對得上，`TestDefaultCategoriesSuggestSections`）。總索引與職位索引（`RenderNoteIndex`、`RebuildNoteIndexes`）照檔頭決定性產生，寫入後、vault 的 `topic`／`topic_category`／`agent` 變更與啟動時重產，內容沒變不寫，位置上是主人自己的檔（檔頭沒有 `generated_by: evergenie`）不蓋；「主人」算所有職位跟進，開場時它的標題降成一般文字。`NoteProblems` 給 doctor 黃字（檔頭不合、放錯位置、名字跟檔名不同、分類沒有說明檔、索引不符、記憶核心超過上限，`max_lines` 沒寫或還是 `200` 當 60）。封存的職位不能寫、不能被列為跟進、不產生職位索引；新建主題或分類的位置已經有主人自己的檔（vault 不當紀錄的，VLT-18）回 `conflict`、不蓋；`NoteProblems` 不看主人自己的檔，只放主人筆記的資料夾不報缺說明檔。`RenameNoteFollower`（`agents mv` 的收尾，AGS-8）把主題 `follow` 裡的舊 id 換成新的、刪掉舊位置核心產生的索引、重產。`ArchiveNote` 封存一份主題（vault `ArchiveNow`，不設 `ArchiveAt`，清道夫不會自動封存主題）：「主人」與分類說明檔不能封存；`Into` 目標要存在、被封存的主題有目標沒有的行（比內容、不比標記）就 `invalid` 並列出，不自動搬；封存後重產索引。一次一件寫入（`notesMu`）。測試 `notes_test.go` → `TestNoteAddMarksWriterAndNeedsCategory`、`TestNoteSetRejectsUnmarkedLines`、`TestNoteIndexesDeterministic`、`TestDefaultCategoriesOnlyMissing`、`TestNoteProblemsMemoryOverLimit`、`TestNoteMarksCannotImpersonate`、`TestNoteIndexKeepsOwnerFileAndDemotesOwnerHeadings`、`TestBrokenCategoryDoesNotBlockStart`、`TestRenameNoteFollower`、`TestNoteSetNeedsRevision`、`TestNoteArchive`、`TestArchivedAgentAndNotes`、`TestOwnerFilesInNotesAreLeftAlone`。

- **PRF-1** — 角色代號：`SlugPattern`（小寫英文開頭、小寫英文與數字）是官方卡的代號；主人自己的角色一律 `my_<名字>`（`MinePrefix`、`MineSlugPattern` `^my_[a-z0-9]{1,24}$`，DEV-154，作者 2026-11-12）：官方代號不收底線，所以自己的永遠撞不到官方、升級帶來同名官方角色也不衝突。`ValidSlug` 兩種都收（讀取、指派、匯出入、測口吻用它）；以前建的、沒有 `my_` 的自己的角色照樣讀得到（搬家工具 `home tidy` 才改名）。`MineSlug(名字)` 把主人給的名字補上 `my_`。跟著角色走的紀錄編號會帶著代號，所以 vault 自訂編號（`givenIDPattern`）與角色包紀錄編號收底線。套件角色的有效代號是 `<套件id>.<slug>`，`PackageCode` 組、`SplitPackageCode` 拆、`IsPackageCode` 判斷（套件 id 那段不合格、slug 不合格、沒有點或多一個點都不算），所以三種來源不會撞名。測試 `personaref_test.go` → `TestSplitPackageCode`。
- **PRF-2** — 代號裡套件 id 那一段的格式只用來拆代號（不匯出）；套件 id 本身的規則歸 packages（manifest 的 `idPattern`），兩邊一致由 packages 的 `TestPersonaCodeAcceptsPackageIDs` 守。
- **PRF-3** — 來源與狀態的字：`SourceOfficial`、`SourceMine`、`SourcePackage`；`StatusLive`、`StatusDesign`。Evidence `personaref.go`。
- **PRF-4** — `CardInfo{Record, Source, PackageID, Inactive, Status}` 是名冊讀一張卡的結果；`Status` 由角色庫判斷後填（只有我的卡與套件的卡能是設計中），名冊只比對 `Status == StatusDesign`。Evidence `personaref.go` → `CardInfo`。
- **PRF-5** — `PackagePersona{Package, Slug, Path, Tier, Active, Reason}` 是 packages 交給角色庫的一張套件角色卡（資料）。Evidence `personaref.go` → `PackagePersona`。
- **PRF-6** — `ParseCard(data)` 讀人設卡檔頭：`---` YAML 與舊的 `+++` TOML 都認（名冊與角色庫共用）。測試 `TestPersonaReadsBothFormats`。

## 設計決定
- **D-31** — 角色庫（人設卡的列出、新增、編輯、檢查、上線／設計中、說話層強度）由核心做，不做成附程式的套件（2026-11-01 起核心裡的位置是業務模組 `internal/feature/agents/persona`，不再是 `agent` 的一部分；決定本身不變）：人設卡本來就是 `agent` 組裝指令、名冊、doctor 在讀的檔案，指派時也要擋「設計中」的卡。官方角色卡唯讀，角色庫只寫 `personas/mine/`；要改官方卡就「複製成我的」。「設計中」是卡片檔頭的 `status: design`，不是搬資料夾。`personas` 官方套件只留角色包下載。否決：附程式的 `personas` 套件；把設計中做成搬資料夾。
- **D-40** — 法律第 1.1 條的做法：職位＝「平常主動照顧的範圍＋記憶放哪」，不是權限邊界。所有職位預設權限一樣（`full`），個別秘書要不一樣只在設定的「進階」（權限分頁）調。職責樣板不寫「不是你負責的 → 找誰」，改成「不主動去管，但主人叫你就做」；可以建議交給負責的秘書，讓記憶集中。做了別的職位範圍的事，做完傳一句給擔任那個職位的秘書記進她的記憶（名冊沒有那個職位就記自己的）；收到這種傳話記進去就好、不用回，也不算 D-25 的委派。新家一開始就有職位樣板可選（`secretaries`、`health`）；設定精靈只問要哪些職位、每個由哪位角色擔任，權限照預設。否決：每位秘書各自一套權限當預設；精靈一開始就問權限等級。

## 已知限制
- 人設卡改了要重開 session 才生效。
- 角色庫沒有刪除、改代號：直接動 `personas/mine/` 的檔案（被官方蓋住的卡也只能這樣）。
- 測口吻在 `session`（SES-23～25），這裡只組指令（AGT-22）。
- 梗本（AGT-45）：開場只在開對話時組，已經開著的對話裡還看得到剛被別人提過的那條，只能靠說話層的規則不重複。說話層選 `custom`（家裡自己的 `personas/_style.md`）的家拿不到內建 A–D 的「老梗」規則，只有開場梗本那一節開頭的提醒；要完整就請主人把那一節加進 `_style.md`（核心不改主人的檔）。
- 角色庫的寫入只有主人與 `system`；秘書改自己設計的卡是直接改檔案。
- `extras` 與代管的複雜情境還沒做；代管只支援舊系統已有的那幾組。
- personaref：代號裡套件 id 那段的格式跟 packages 的 `idPattern` 各寫一份（base 不能 import 業務塊），靠測試守一致。

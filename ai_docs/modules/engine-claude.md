# 模組：engine-claude（`packages/official/engine-claude`）
Status: DRAFT — 設計 2026-10-23（P0-S7）；2026-10-24 依新傳話架構改寫（D-5、D-24，P3 放行）。

**目的：** Claude 這一家的一切細節：tmux、啟動、hooks 設定格式與事件對照、transcript、權限設定、把文字貼進 session、輸入的來源判斷、動作分類、第一次啟動的對話框。實作 `EngineAPI`，並把 Claude 的 hooks 轉成核心的正規化事件（`EngineHostAPI`）。專有名詞只允許出現在這張卡與這個套件裡（D-21）。
**種類：** 官方套件（附程式；上線前由 `serve` 依內建清單啟動，P6 起由 `pkg` 管理）

介面的語意（事件、`Deliver`、`Ask`、`AnswerApproval`、`resume`）見 `engine.md`；這張卡只寫 Claude 的做法。測試沒寫路徑的都在 `internal/claude/`（假 tmux、假時鐘、錄下的畫面與 payload 當 fixture）。

### hooks 與事件
- **ECL-2** — hooks 寫進**產生的原生設定**，每個 hook 呼叫 `evergenie-engine-claude hook <事件>`，由它呼叫 `EngineHostAPI`：`SessionStart`→`SESSION_STARTED`（`source = compact` 不報：自動壓縮不是新 session）、`UserPromptSubmit`→`TURN_STARTED`（ECL-5）、`PreToolUse`→`ACTIVITY_STARTED`（`SendMessage` 帶要直接傳話給誰、內容）、`PostToolUse`→`ACTIVITY_ENDED`（`SendMessage` 再帶成功與否；可能比收件方開始處理還晚到）、`Stop`→`TURN_ENDED`（帶 `background_tasks` 與最後一則訊息）、`StopFailure`→`RATE_LIMITED`（ECL-38）或 `TURN_FAILED`（ECL-41）、`PreCompact`→ECL-43、`SessionEnd`→`SESSION_ENDED`（ECL-44）、`Notification`（`idle_prompt`）→`IDLE_HINT`（額度例外 ECL-38）、`PermissionRequest`→`RequestApproval`。狀態類 hook 不輸出文字、逾時 ≤ 5 秒、核心不在／payload 不是 JSON／逾時都 exit 0；`PermissionRequest` 的 `timeout` ≥ 600 秒。寄件人位址 `uds:…` 經 `peers/` 還原成名字。測試 `TestHookToEngineEventMapping`、`TestGeneratedHooksTimeouts`、`TestHookExitsZeroWhenCoreDown`、`TestDirectMessageFromPreAndPostToolUse`、`TestDirectReplyToSenderAddressResolvesToName`。
- **ECL-5** — 輸入正規化（`UserPromptSubmit`）：`<cross-session-message from-name="X">` → 來源 `peer`、對方 X；`<task-notification>` → `system`；開頭的 `[Request interrupted by user…]` → 上一輪被中斷；`<pasted_content>` 外框去掉；其他 → `typed`。同時把來源、時間與輸入開頭（正規化後前 400 字，`head`）寫到 `runtime/engine-claude/turns/<session>.json`，給核心不在時的 `hook check` 與確認送出（ECL-42）用。測試 `TestInputNormalize`、`TestInputNormalizeReportedAndRecorded`。
- **ECL-11** — 問題（`AskUserQuestion`）：`tool_input` 轉成中立的 `Question` 送 `RequestApproval`；`Decision.answers` 轉回原題目加 `answers`（key 是題目全文，不改字）回給 Claude。權限確認的決定轉成 `allow`／`deny`（附理由）。測試 `TestQuestionRoundTrip`、`TestPermissionRequestDecisions`。
- **ECL-12** — 會輸出的 hook 只有兩個：`UserPromptSubmit` 的 `hook context`（叫 `GetContext`，非空才印）、`PreToolUse` 的 `hook check`（分類後叫 `CheckAction`：`deny`／`ask` 印 `permissionDecision`，`allow` 不印）。測試 `TestContextHookOnlyWhenNonEmpty`、`TestCheckOutputShapes`。
- **ECL-13** — 動作分類（`hook check`，表在 `classify.go`）：讀、寫、commit、push、刪除、對外發訊息、花錢、改設定；`Bash` 用 `&&`、`;`、`|` 串的逐段分類取最嚴，`( … )`、`{ …; }` 照裡面的指令；不認得的工具算 `write`。`evergenie` 子指令：唯讀子指令（`list`／`get`／`show`／`stale`／`waiting`、`status`、`roster`、`docs`（跟著程式的說明文件）、`sessions opened|peek|attach`、`trust scan|diff|denied`、`quota`、`preflight`、預演與沒 `--apply` 的）與 `say`（回覆寄件人的退路）算讀；帶 `--apply`／`--fix` 的、`policy request`、`packages reload|install-go`、`data add|set|rm` 算寫；`setup`、`service`、`tailscale`、`policy decide|revoke`、`agents link --apply`、`config set`、`web` 的寫入子指令算改設定；逐條在 `classify.go` 的表。核心不在時：來源 `peer` 且不是讀 → `deny`，其他不印。測試 `check_test.go` → `TestCheckClassifyTable`、`TestCheckCoreDownFallback`。
- **ECL-38** — 額度用完（`limit.go`）：平台照樣觸發 `UserPromptSubmit`，但那一輪沒呼叫到模型：沒有 `Stop`，改觸發 `StopFailure`（`error = rate_limit`，`last_assistant_message` 例「You've hit your 5-hour limit · resets 6pm (Asia/Taipei)」），對話記錄最後一則是平台合成的 assistant（`isApiErrorMessage`、`apiError: usage_limit_reached`、`apiErrorParams.rate_limit_info.resetsAt`）。收到 `rate_limit`（或最後一句是那一行）就報 `RATE_LIMITED`，`until` 先取對話記錄最後 256KB 的 `resetsAt`／`quotaLimits.resetsAt`，沒有再從那一行認（`6pm`、`6:30pm`、`Nov 3, 9am`、時區、舊版 `|<epoch>`；「6pm」指之後第一個 18:00），認不出就空；模型自己講到 limit 的話不算。`Notification`（`idle_prompt`）時最後一則還是額度用完、還沒到恢復時間（說不出時間的只看 15 分鐘內）就報 `RATE_LIMITED` 不報 `IDLE_HINT`。測試 `limit_test.go` → `TestLimitTextAndResetFormats`、`TestTranscriptLimitRealSample`（`testdata/limit/`）、`TestStopFailureReportsRateLimited`、`TestIdlePromptAfterLimit`。

`runtime/engine-claude/` 底下：`<帳號>/`（產生的設定；不進 git）、`turns/<session>.json`（這一輪的來源、時間、`head`）、`launches/<session>.json`（啟動記號，ECL-24）、`transcripts/<session>.json`（對話檔位置，ECL-30）、`peers/<session>.json`（寄件人位址 `uds:…` → 名字，ECL-2）；session 筆記見 `schemas/session.md`（由 `session` 寫）。

## 依賴
`sdk`

## 錯誤
`ERROR_CODE_UNAVAILABLE`（`claude` 或 tmux 不在、帳號未登入）、`ERROR_CODE_NOT_FOUND`（沒有這個 session）、`ERROR_CODE_INVALID`（政策欄位不合）。

## 不變條件
- `Start` 的 `Account` 與 `engine_config.config_dir` 必填；帳號還沒產生過設定檔時先用空政策產生一份；同名 session 還活著回 `Conflict`（`TestStartValidation`）。
- `Stop` 殺掉 tmux 後自己報一次 `SESSION_ENDED`（`stopped`），被砍的 Claude 不保證觸發 `SessionEnd`；核心對重複的結束事件冪等（`TestStopKillsAndUnknownIsNotAnError`）。
- 每個 session 記住自己的 tmux socket：`Start` 先記 `engine_config.tmux_socket` 再查存活；引擎重開後從核心狀態檔的 `attach` 補回，沒紀錄才用 `eg`；`home.toml [runtime] tmux_socket`（D-35）由核心蓋到每個帳號，正式家與開發家互不干擾（`socket_test.go` → `TestStartChecksAliveOnConfiguredSocket`、`TestOrphanSocketRecoveredFromAttach`）。
- `evergenie-engine-claude hook` 永遠 exit 0，`serve` 要家目錄（`cmd/evergenie-engine-claude` → `TestHookNeverFailsAndServeNeedsHome`）；`account-defaults` 印一個 JSON 物件（`TestAccountDefaultsPrintsEngineConfig`，ECL-64）。
- 其他不變條件寫在各條規則，跟守它的測試在一起。

## 已知限制
- 擋住輸入框的選單（ECL-66）：選單的樣子是照回報的文字合成的，真機上它跟輸入框、框線怎麼排沒有擷取過；幾種排法（取代輸入框、畫在輸入框裡、緊貼在輸入框上面）都處理，真機沒驗；排法不在這幾種裡就不會自己按取消，由 ECL-67 告訴主人。`--settings` 檔裡的 `skillOverrides`（ECL-69）平台會不會採用，文件沒寫明、真機沒驗，所以 ECL-66 照留；已經開著的對話要重開才吃到新設定。對話指令（ECL-46）遇到這個選單不會自己按取消。
- 收掉舊視窗（ECL-68）：舊視窗裡她正在做的那一輪會被中斷（核心已經把它記成停了、那一輪的話已經收尾或放回排隊），主人手動接在那個視窗上也會被踢出來；`#{pane_start_command}` 的格式只在 tmux 3.6a 看過（印指令稿的純路徑）；指令稿資料夾路徑含空白時 tmux 回的啟動指令對不上，會當成不是這個家開的（回 `conflict`）。`Alive` 把 tmux 叫不起來、逾時也當成不在，沒有改。
- 實測（2026-10-24）：`PreToolUse` 回 `deny`／`ask` 在 auto 模式有效；`UserPromptSubmit` 的輸出變成附加內容；`from-name` 等於 `--name`。跨帳號的 `SendMessage` 不通，跨帳號由核心的 `say` 送。
- 動作分類靠指令字串判斷，會有漏網和誤擋；平台的分類器仍然開著當第二道網。
- 貼上到送 `Enter` 之間 1 秒，送前會再看畫面，「看完到按下」之間仍有極短空窗。
- 確認送出（ECL-42）沒有真機驗，是照畫面樣本與 hook 順序推的；輸入框改版時，忙著插話會變成「沒確認送出」由核心重試；空框提示只認「Try "…"」。
- 對話指令（ECL-46～48）沒有真機驗：「Switch model?」「Change effort level?」的字樣、她忙時平台收不收 `/model`、斜線指令的自動完成會不會吃掉 `Enter`、`/compact` 做完前輸入框的樣子、帶名字的上緣線，都是照 DEV-100 回報推的；樣本是合成的。`/model`、`/effort` 在 Claude Code 會存成帳號的預設（新 session 也用），不只這段對話。
- 模型與力度（ECL-49）2026-11-02 在開發家（真的 Claude，2.1.316）驗過：SessionStart 給別名 `sonnet`、做完一輪換成 `claude-sonnet-5-5`／「Sonnet 5.5」，力度 `medium`；`/model`、`/effort` 沒在真機下（會改帳號的預設）。Stop 讀不到這一輪的回話時會多等最多 0.8 秒才回報「這一輪結束」（例如她忙著時主人換了模型、換完還沒回話），排著的話也跟著晚這麼多送；有沒有對話記錄檔是先看的，沒有就不等。平台改了掛勾欄位名就變成空的（看板不畫，不會畫錯）。沒帶 `--model` 開的 session，要等 SessionStart 或第一輪做完才知道模型；沒帶 `--effort` 的，要等第一個帶力度的掛勾（工具、Stop）。同帳號別的 session 用 `/model` 改了帳號的預設，這段要到她下一輪做完才換。`/model` 做成時對話記錄的「Set model to」可能還沒寫進去，名字先顯示別名（「Opus」），她下一輪做完才換成完整的名字。`--effort` 收 low、medium、high、xhigh、max（`validEfforts`；2026-11-02 作者「effort 就是 extra 就好」，兩台都是 2.1.316、`claude --help` 列了 xhigh）；設定寫了不收的字（例 `High`、`turbo`）就不帶，核心卻先記了設定的值，看板會顯示這個沒生效的力度，直到第一個帶力度的掛勾更正。
- `SetPermission` 只產生 hooks、`additionalDirectories`（`Repos`，只加不限制）與 `autoMode.allow`；`PermissionPolicy` 的 `Allow`／`Deny` 還沒轉成原生規則（秘書的能力不能因新系統變少）。
- `Start` 忽略 `FirstMessage`（核心一律經派送器送第一則，`TestFirstMessageIgnored`）；`RemoteAccessURL` 回空字串。
- 貼上後遇到確認框、不送 `Enter` 時，已貼進框的字不會被清掉；核心重送可能讓框裡有重複的字。
- 附帶的 tmux（ECL-63）：x86_64 那份是在 Apple 晶片的 office（`<登入名>-office`）上交叉編的，那台不能跑 x86_64（沒有 Rosetta），只驗了晶片、連結與 terminfo 路徑格式，沒有實跑。下載版的 `attach` 用 `<app>/fixed/<產品名>`（舊的包是 `current/bin/tmux`）：升級後印的是新版的 tmux。附帶的與 Homebrew 的、或升級前後的 tmux 版本不同時，舊的 tmux server 會被新的那支當 client 來連；tmux 3.x 之間的協定版本相同，[推測] 能連，沒實測跨版本。預設 TERM 是 `tmux-256color`：macOS 14 以前內建的 terminfo [推測] 沒有這個名字，session 裡用 terminfo 的程式（less、vim）可能說「終端機不完整」，Claude 本身不受影響。
- 權限視窗記在 tmux 名下（ECL-65）：會跳視窗的那一步（主人按「允許」、之後升級不再問）沒有實測，留給電腦秘書跟主人約時間做（做法在 `runbooks/release.md`「附帶的 tmux」）；不跳視窗的部分 11-13 實測過（系統紀錄裡負責的程式是經 `disclaim` 開的那支 tmux）。已經在跑的 tmux server 不會變：升到這版後要等那個 server 關掉重開（session 全關或重開機）才記在新的名下。從還不會放 `<app>/fixed/` 的舊核心升上來的那一次，引擎用 `<v>/fixed/` 那支（路徑帶版本號），下一次升級放好 `<app>/fixed/` 後換過去，會再問一次。退回舊版會把 `<app>/fixed/` 換回舊版那份（system 卡 UPD-15），舊版的包沒有 `fixed/` 就不動（那種包的引擎也不看 `fixed/`）。tmux 改版換掉 `fixed/` 那支時，還在跑的舊 server 會被新的那支當 client 來連（同上）。

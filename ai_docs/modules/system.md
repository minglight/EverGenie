# 模組：system（`internal/feature/system`）
Status: DRAFT — 2026-11-02 S8-3 合併 settings、update、doctor、accounts、host、rules 六張卡，pending author review.

**目的：** 這個家與這台電腦本身：家的設定與看板連多台的設定、備份整理、安裝前檢查；整個家的備份、還原與搬到新電腦；EverGenie 自己的升級與家的遷移；整體健康檢查；AI 帳號與用量；launchd 服務與 Tailscale；規矩頁（憲法、宗旨、法律的呈現、修改、版本與提案）。
**種類：** 業務塊（7 塊之一；子套件 `system/settings`、`system/update`、`system/doctor`、`system/accounts`、`system/charter`〔規矩頁，原 `rules`〕、`system/homebackup`、`system/backupsweep`〔每週的備份掃描〕，加只給同塊與命令列用的函式庫 `system/host`；法律第 8 條）

## NEVER
- **SET-N1** — settings 不 import 別的業務塊（doctor 的結果走 API client 拿，同塊的 `doctor.Print` 直接用）；不自己寫「是不是主人」的判斷；不碰系統（launchd、brew）。
- **UPD-N1** — serve 不自己換自己：升級一定在另一個行程（`upgrade --apply`，`Setsid` 脫離）。
- **UPD-N2** — 不 import 別的業務塊（depcheck 照路徑擋）。
- **UPD-N3** — 核心自己的遷移只能往前相容（舊版照樣讀得懂），退回時不倒退；套件的資料轉換可能不相容，所以退回靠升級前的備份整份還原（UPD-9），不寫反向轉換。
- **DCT-N1** — doctor 不修復、不寫任何資料；launchd、Tailscale 的檢查經 `Commands` 的參數注入。
- **DCT-N2** — 不複製別的模組的判斷：各模組的檢查一律由它自己的 `Checks()` 提供。
- **DCT-N3** — 輸出不帶秘密（金鑰、裝置網址、設定檔內容）：`settings/*.toml` 只報檔名與行號（CLI-N4）。
- **ACC-N1** — 帳號編輯與用量的實作不留在 platform 或 api。
- **HST-N1** — 不要密碼的事才做：不跑 `sudo`；`--fix` 只接受 `brew install`。
- **HST-N2** — 不另起專用的 Tailscale 節點、不分享電腦上其他服務；不在後台建服務、不改 ACL、不核准主機（`setup` 只提示）。
- **HBK-N1** — 還原不在服務跑著時直接換家裡的檔（一定經 `pending.json`＋重開）；不留「換了一半」的家開服務；備份檔不收秘密檔裡推播金鑰以外的東西、不收 AI 帳號的登入資料。
- **HBK-N2** — 不 import 別的業務塊；通知在 `Deps` 定義小 interface 由組裝接上；家的遷移清單與驗證由組裝傳進來（`KnownMigrations`、`ApplyOptions.Verify`）。
- **BSW-N1** — 不掃整個使用者家目錄（AGT-37）：範圍只有 BSW-2 那四處，範圍外的資料夾一個都不讀。
- **BSW-N2** — 不刪掃到的東西、不改名（BSW-5 的 `runtime/backups/` 除外）；刪之前要主人或電腦秘書看過報告、照備份規則再查一次。

- **RUL-N1** — 不讓秘書直接改規矩文件：主人以外的 `save`／`restore`／`decide` 一律擋（法律第 1.7 條）。

- **RUL-N3** — 不用 git 存版本、不呼叫 git。

## 設計決定
- **D-43** — 看板用 Tailscale 服務露出（作者 2026-11-01）：跑 EverGenie 的機器一律 tag 身分；每個家一個服務 `svc:genie[-dev]-<owner>-<machine>`（`env = "dev"` 加 `-dev`；例 `genie-amy-mini`），網址 `https://<服務名>.<tailnet 網域>`、一律 443，不再用埠分家。同一台第二個同類的家預設不露出，要露加 `-<用途>`、不能跟已在用的同名。設定在 `home.toml [web] service`（不含 `svc:`），`setup`／`down` 只動名稱與目標都對上的；沒寫的家照舊機器 serve。服務由主人在後台建、核准，EverGenie 不碰 ACL；CLI 先用 App 內附的那支。否決：從標籤自動推服務名（後台要先建）；每個家用不同埠掛在機器名下（網址要記埠、跟機器綁死）。

## 已知限制
- settings：沒有 `mode` 指令（在看板設定頁改）；`web sites|allow add|rm` 讀寫之間沒有鎖，同時改時後寫的蓋掉先寫的。
- update：子行程靠 `os.Executable()` 找自己（測試用假執行檔）。部署工具（`scripts/deploy.sh`）的部署後檢查沒有「部署前就紅」的基準，家裡本來就有紅字時會被當成這次部署的錯（`evergenie upgrade` 那條路有基準）。整理過資料的部署之後又部署了別的版本，`upgrade --rollback` 會拒絕（備份留著，要找回資料靠秘書手動）。手動退回會把 `home.toml` 與編號檔一起還原到升級前（升級後改的設定在 `rollback-*.tgz`）。第一個帶「升級紀錄記 `migrations`／`backup`」的版本不要同時附官方套件的 `[[migration]]`：那次升級是舊程式在跑，不會記。`upgrade --rollback` 在程式資料夾 `git checkout`，一個程式資料夾配好幾個家時只還原下指令的那個家的資料。下載版（UPD-11～13）：版本清單與包只靠 https 與 sha256，還沒有簽名；晶片照執行檔自己的 `GOARCH` 挑，用 Rosetta 跑 amd64 的版本會一直升 amd64 的包；指標檔 `evergenie.local.toml` 的找法（PLT-21，`bin/` 的上一層）在下載版會找到 `versions/<版本>/`，裝法（DEV-155 S3）要另外決定；升級沒成功時還不能從看板把日誌打包給人（UPD-14 只給位置）；比 UPD-14 舊的 `state.json` 沒有 `outcome`，看板只說「沒成功」、不說有沒有換回。`rescue.json` 是升級行程寫的，升級行程被硬殺（沒走到收尾）時不會有，那時看板首頁沒有「退回上一版」，要請秘書手動 `upgrade --rollback`。
- doctor：一個 `Check` 只回一個結果，同類多個問題併成一條；`config.launchd`、`config.tailscale` 在 `cmd/evergenie`（要用 host）。
- accounts：用量的暖機與額度通知由引擎負責。
- 手機連線（SET-10～13）：Funnel 的關法、「後台還沒開 HTTPS」的訊息樣子、重新 `serve` 會不會收回 Funnel，都是照 Tailscale 1.104 的輸出格式與文件寫的，用假的執行檔測，沒有在真的 Tailscale 上開關過；第 3、4 步（手機裝 App、掃 QR code）偵測不到，只有從看板的 Tailscale 網址打開時才算做好。
- host：沒在真的 launchd、brew、Tailscale 上跑過；Tailscale JSON 照真機（1.104.2）的輸出對過，改格式時 `status` 顯示「不知道」、doctor 黃字、`setup`／`down` 不動手；換掛法或服務名時 `setup` 不關舊的。
- homebackup：還原要服務在跑、而且這個家現在的 `home.toml` 讀得懂（家已經壞到開不起來時，用 `init --from-backup` 另建一個家）；留現況到換上去之間（幾秒）寫進家裡的東西會不見；還原後 `home.toml` 的註解不留（重新編碼）；還原前開著的秘書對話會先收掉、重開後照排程與常駐規則再開（HBK-12），收不掉的那幾個內容還是還原前的；換好之後跑的家的遷移只動換上去的那幾塊，驗不過整個換回去（HBK-5）；備份只放這台電腦，電腦壞了就沒有（法律第 7 條，要另存主人自己下載）；放在狀態資料夾的官方角色不在備份裡（靠角色包拿回）；第 1 版佈局的家只收 `runtime/share`、`runtime/art` 兩個附件資料夾，家資料夾最上層其他的東西不收；第 2 版的備份還原進第 1 版的家，`media/` 底下 `share`、`art` 以外的不會放進去；`settings/` 整個照備份的（`relayout.json` 這類綁機器的紀錄也會帶到新電腦）；沒有容量上限（手動的與還原前留的各最新 7 份＋30 天內的都留，附件很大的家會佔很多空間；畫面只顯示一共多大）；這個家的秘密檔讀不懂時不放推播金鑰（手機通知要重開）；看板上傳上限 2 GB（更大的用指令 `backup restore <路徑>`）；改設定前的小備份（`runtime/backups/`）由每週的備份掃描照規則清（BSW-5），這裡不清；`home.toml` 的 `[backup]` 不讀（開發家舊的那段沒有作用）。
- charter：本機 API 身分只看 `by` 字串（秘書拿掉 `EVERGENIE_AGENT` 就是主人）；連得到看板 port 的就是 `owner(web)`；差異只到「行」；提案過期只能退回重送；看板外直接改檔，下次經看板改之前才補版本。
- backupsweep：「在用」只認寫在開機服務設定、執行中程式的指令列、終端機多工器視窗的路徑；程式開著的檔（`lsof`）、cron、其他排程工具不查。執行中的程式與終端機的視窗只看當下，剛好沒在跑的服務查不到（開機服務的設定檔查得到）。git 工作目錄裡的檔一個工作目錄問一次 `git ls-files`，很大的 repo 會慢一點。報告只留最新一次。規格的例外「各 project 檔 `## 現在在跑的` 列的路徑」沒有自動讀（那些檔在家的 docs/，格式不固定），要略過的請主人或電腦秘書加進 `settings/backup-sweep.toml`。沒在真的兩台上跑過一整輪（開發家的實機測試在 DEV-163 之後另做）。

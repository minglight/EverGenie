# 模組：packages（`internal/feature/packages`）
Status: DRAFT — 2026-11-02 S8-3 合併 packages.md、data.md；S8-5 套件模組搬成子套件 `packages/pkg`，pending author review.

**目的：** 套件：探索、安裝、偵測改動重編、行程監督、能力宣告、擴充點、fork 與更新整理、使用者自己的套件（建、匯出、認領）（D-2、D-3）；加上給套件與看板讀寫資料的 sdk `vault` 服務（`packages/data`）。
**種類：** 業務塊（7 塊之一；子套件 `packages/pkg`〔套件，模組名 `pkg`〕、`packages/data`〔原 `data`〕；根目錄只組裝；法律第 8 條）

## MUST
### packages/pkg（套件）
- **PKG-1** — 套件是一個資料夾加 manifest（`package.toml`），分純資料與附程式兩種；附程式的用 Go SDK 的獨立行程。
- **PKG-2** — 改了 `packages/mine/` 之後自動偵測、重編、重啟，使用者不用打指令。
- **PKG-3** — 電腦沒有能用的 Go 時照 D-27：不自動裝、不只丟指令；`failed`＋白話原因＋通知；能幫忙下載時（下載版、有這台晶片的包）才帶 `remedy = install_go`，白話是「這個套件要先裝編譯工具（Go，約 70MB，裝在程式自己的資料夾裡），要我裝嗎？」（大小照 PKG-65 寫死的包算）；不能幫忙下載時不帶補救代號，白話寫要怎麼做，主人同意後 `InstallGo`（`confirmed = true`），裝好自動重編。找 Go、下載 Go 照 PKG-65。
- **PKG-4** — 擴充點：官方套件宣告可以改的地方；擴充點被拿掉時看板警告，不會壞。三種都真的生效（DEV-154）：`setting` 的值套件自己讀（`ListExtensions`）；`prompt_append` 的值由 `PromptAppends(職位)` 交給名冊，接在那位秘書指令的「附加規則」後面成為「套件補充」一節（主人設了用設的、沒設用 `default`、清成空字串＝不要；宣告 `agent` 的只給那個職位，沒宣告每一位都接；套件停用或被拒就不帶；值上限 4000 位元組；下次開對話才帶進去；宣告 `until_record = "<自己的資料種類>/<編號>"` 的只在那筆紀錄還不存在時帶，紀錄出現〔含封存的〕就不帶，讀不到〔vault 沒接、出錯〕也不帶〔fail closed〕，給「只講一次」的話用，核心只看紀錄在不在、不認得內容，DEV-157，測試 `TestPromptAppendUntilRecord`）；`page_slot` 是套件頁面裡的 `<host.Slot id="<套件>.<擴充點>">`，別的套件的頁面宣告 `slot = "<套件>.<擴充點>"` 就掛上去（`menu` 算位置），它沒有值、`SetExtension` 對它回 `INVALID`。秘書用 `evergenie packages extensions [<套件>]` 看、`packages set-extension <套件> <擴充點> (--value|--file|--clear)` 改。 把關（DEV-154 審查，憲法第 10 條）：別人分享的套件（installed）`prompt_append` 的預設值不自動生效，主人本人在擴充點設了值才帶（`SetExtension` 對這一層的 `prompt_append` 只收主人署名，秘書設會被擋：它可能是被套件的說明帶著走）；`default` 不超過 4000 位元組、每個擴充點的 `description` 只能一行且不超過 200 位元組，不合套件被拒；補充內文開頭是 `#` 的行由名冊降成普通文字（`demoteHeadings`），不能自己開一節；設定檔手改成超長的只帶前面一段，健檢 `packages.prompt_append` 黃字提醒。測試 `TestPromptAppendFromSharedPackage`、`TestDemoteHeadings`。
- **PKG-5** — 整包複製官方套件（fork）的入口已關（DEV-154）：`service.Fork`（`/api/package/fork`，看板、CLI、套件都走這裡）一律回 `FORBIDDEN` 與 `ForkClosed` 的白話說明（改用擴充點或自己做套件），看板套件頁沒有「複製一份來改」。以前複製過的（`mine` 裡帶 `[fork]` 的）照舊：記著基準版本；官方更新後產生「基準→新版」的差異清單檔給 AI 整理成白話，逐項問使用者要不要 merge。
- **PKG-6** — 一個套件的行程掛了只影響它自己，核心重啟它並發 `system.alert`。
- **PKG-7** — 上線前不改 `skills/`（技能與套件是兩回事）。
- **PKG-8** — 上線前不改 `framework/bin/` 的小工具。
- **PKG-9** — 四層探索：核心 → 官方 → 分享的 → 自己的；同 id 自己的優先（視為 fork），分享的不能蓋掉官方；一個套件有問題（manifest、協定、相依缺少或成環、編不過）只讓它自己不載入並白話說明，其他照常。名字含 `.bak-` 的資料夾是備份（備份規則的 `<原名>.bak-<日期>-<原因>`，system 卡 BSW-4），不是套件：探索與改動偵測都略過。`mine`、`installed` 裡沒有 `package.toml` 的子資料夾是主人自己放的東西，不是套件：不載入、不列、不輪詢改動（DEV-154；官方資料夾少了 `package.toml` 照舊是壞掉的套件）。
- **PKG-10** — 套件的資料一律放 `vault/pkg/<套件 id>/`（`Hello` 回的 `data_dir`；寫入仍經 vault）；解除安裝不刪資料（D-27、PKC-7）。
- **PKG-11** — 資料是宣告式的（D-28）：`[[contributes.data]]`＋`schemas/<種類>.toml`；每次重掃後，啟用且沒被拒的套件把種類註冊進 vault（`<套件 id>.<種類>`），其他套件的種類拿掉（資料留著，重新啟用就回來）。規格不合格套件 `rejected`（`field = "contributes.data"`）。不做套件自己的 RPC。
- **PKG-12** — `Sync`（`packages sync <套件>`，D-28）：預設只預演，`apply` 才套用、只有主人；已存在的排程不改、addendum 不動；掃描時絕不自動改秘書或排程。`agent` 只同步那個職位；沒給 `agent` 時略過**名冊上還沒有的**選用職位（樣板 `optional: true`；封存過的也算還沒有，不回衝突）與它的排程，回應 `optional` 列出略過的，已經在名冊上的照一般職位同步（DEV-157；例：開發工坊帶的生圖 `art`，admin 卡 ADM-39）；`persona` 是新增秘書用的人設。`package.list` 每個套件帶 `agents`（職位 id、`duty`、顏色、`optional`）。看板白名單開 `package.sync`（`by` 換成 `owner(web)`）。
- **PKG-13** — 選用套件（`optional = true`）：沒有 `settings/packages.toml` 紀錄時預設不啟用（`stopped`、種類不註冊、依賴它的被拒）；`SetEnabled` 對它一律寫明確值；`packages enable|disable` 的 help 寫明要先問過使用者；設定精靈列出它們。
- **PKG-14** — 已廢：2026-10-31 法律第 7 條改，兩家不連線。
- **PKG-15** — 從 git 網址安裝（`https://`、`ssh://`、`git@`、`file://`）：一定要 `confirmed = true`（沒有回 `INVALID`，不碰網路）；帶帳號密碼 `INVALID`；沒有 git `UNAVAILABLE`。clone 到隱藏的 `.install-*`（逾時 120 秒，不持有模組的鎖）→ 版本＝`ref` ＞ 最大的 semver tag（預發行不算）＞ 預設分支 → 複製（不帶 `.git`）、寫 `.source.toml`（`schemas/package.md`）→ 驗過才 rename；失敗不留暫存；有 `Problems` 不裝。
- **PKG-16** — `Preview(source, ref)`：抓到隱藏的 `.preview-*`，回名稱、版本、`runs_program`、帶來的秘書／頁面／排程／資料種類／角色、能力、`core`、實際 `ref`／`commit`；不合格、跟官方同名、`core` 不符、缺相依放 `problems`（白話，不是錯誤），已裝同 id 標 `exists`；用完刪暫存。
- **PKG-17** — manifest 的 `core` 限制核心版本：不符 → `rejected`「這個套件要 EverGenie <限制>，你現在是 <版本>」；開發版當正式版；版本認不出（短碼、`dev`）不擋、`Warnings()` 寫一句。本機資料夾安裝時也擋。
- **PKG-18** — `Outdated`：有 `.source.toml` 的套件用 `git ls-remote --tags --refs` 看最大 semver tag（同時最多 4 個、每個 20 秒），較新就列；抓不到放 `failed`。`Upgrade(id, ref)`：只限有 `.source.toml` 的非官方套件；新版暫存驗過 → 舊的改名 `.old-*` → 換進來重掃；新版 `rejected`／`failed` 就換回並回 `CONFLICT`「已換回舊版」；`vault/pkg/<id>/` 不動；已是最新 `CONFLICT`。
- **PKG-19** — `PackagePersonas()`：回各套件 `[[contributes.persona]]` 的卡（套件 id、slug、卡檔路徑、是否有效），給角色庫的第三個來源；停用與讀得起來的被拒也列（`Active=false`）讓已指派的秘書讀得到；經符號連結跑出套件資料夾的略過。組裝時注入角色庫。
- **PKG-20** — `New(id, name)`（`packages new`）：在 `packages/mine/<id>/` 建鷹架（純資料的 `package.toml`、一位秘書樣板、頁面 `/p/<id>/index` 與選單、`personas/`、`schemas/`、`README.md`）。id 要 `^[a-z][a-z0-9-]{1,30}$`、不在 `ReservedIDs`（與 `conventions/user-features.md` 一致），否則 `INVALID`；跟已有的套件或別的套件帶來的職位同名 `CONFLICT`（說是誰）。建好重掃重編；不建秘書（`sync` 才建）。
- **PKG-21** — `EditedOfficial(ctx, home)`：官方套件資料夾在 git 工作樹裡時，回有未提交修改／刪除／新增的官方套件 id；不是工作樹、沒有 git、讀不出來回空。下載版的官方資料夾（解開符號連結後是 `<app>/versions/<版本>/packages/official`，`platform.IsDownloadInstall`）、或往上（解開符號連結、轉成絕對路徑後）找不到 `.git` 的，直接回空、不叫 `git`：乾淨的 Mac 上 `/usr/bin/git` 是要先裝開發者工具的空殼，一叫就跳視窗；下載版放在別的 repo 底下（家目錄是設定檔 repo）也不誤報（`TestEditedOfficialOutsideWorkTreeDoesNotRunGit`、`TestEditedOfficialSkipsDownloadInstallInsideRepo`、`TestEditedOfficialFollowsSymlinkIntoRepo`）。
- **PKG-22** — `AddPackagePersona(pkgID, slug, card)`（`personas_write.go`，實作角色庫的 `PackageWriter`）：只動 `packages/mine/<id>/`——官方與 installed `FORBIDDEN`、沒有這個套件 `NOT_FOUND`、卡或宣告已存在 `CONFLICT`、id 不合格或符號連結 `INVALID`。現有 manifest 驗得過 → 備份到 `runtime/backups/packages/` → 寫卡 → 尾端附 `[[contributes.persona]]` → 驗過；任何一步失敗刪卡、manifest 倒回。成功後重掃（不重編）。
- **PKG-23** — 樣板預設角色：`agent.md` 標頭選填 `persona`（格式不合套件 `rejected`）。`Sync` 新增秘書的角色：`req.Persona` ＞ 樣板 ＞ `SyncHost.DefaultPersona()`，預演回 `SyncAgent.Persona`／`PersonaFrom`；來源是樣板且 `CheckPersona` 不過 → `INVALID` 提示 `--persona`；都沒有則套用時 `INVALID`。
- **PKG-24** — `SyncHost` 有 `CheckPersona(persona) error`（組裝接名冊的 `CheckAssignable`；測試的假主機要實作）。
- **PKG-30** — `Export(id, out, git, allow_findings)`（`export.go`）：只限 `mine`、`installed`（官方、fork `FORBIDDEN`）。不跟符號連結；不帶 `.git`、`.fork-base`、`.source.toml`、`node_modules`、`.DS_Store`、隱藏暫存、編譯產物（清單在 `export.go`），略過的寫進 `skipped`。`out` 要完整路徑（空＝`runtime/exports/<id>-<版本>`），`.tar.gz`／`.tgz` 打壓縮檔，其他是資料夾；不能在套件資料夾、`packages/`、`vault/` 裡（`INVALID`）；已存在 `CONFLICT`（空資料夾可以）；先寫隱藏 `.export-*` 再 rename。
- **PKG-31** — 匯出的符號連結：指在套件內的略過；指到外面或指不到的，整個匯出 `INVALID` 並全部列出、什麼都不寫，`allow_findings` 不能放行。
- **PKG-32** — 個資掃描（`privacy.go`，寫任何東西之前）：看檔名（`.env`、`secrets/`、私鑰與憑證檔…）並逐行掃前 2MB（二進位只看檔名）：金鑰（常見前綴、JWT、`token`／`password` 欄位的值、高亂度長字串）、家的絕對路徑、email（範例網域不算）。有發現且沒 `allow_findings` → `blocked = true`、什麼都不寫，回 `findings`（檔案、行號、種類、只露開頭 4 字與長度的說明）；有 `allow_findings` 照樣匯出並回清單。
- **PKG-33** — `git = true`（只限資料夾）：多寫 `.gitignore`（已有就只補沒有的行），不跑 git。`Preview` 的 `personas` 每個宣告一筆 `{id: <套件id>.<slug>, slug, name, avatar}`。安裝後重掃，`PackagePersonas()` 馬上帶出新角色；`Upgrade` 不讀寫 `settings/packages.toml`、不碰 `vault/pkg/<id>/`。
- **PKG-40** — `ClaimNotify(id, agent, persona)`（`claim.go`）：秘書或主人請核心對還沒人負責的職位發認領通知（`approve`，選項「好，用 <角色>｜換一個｜之後再說」，`source = package`、`claim = <職位 id>`）。`agent` 空＝第一個沒人負責也沒問過的職位，跳過選用職位（只剩選用的回 `CONFLICT`、訊息寫出是哪個選用職位沒問；指名照樣發，DEV-157）；套件不在 `NOT_FOUND`、被拒或停用 `INVALID`、已有人負責 `CONFLICT`。角色：給了要過 `CheckPersona`，沒給用 `SuggestPersona`，都沒有 `INVALID`。**只發通知**：不建秘書、不啟用、不碰 `Sync`。
- **PKG-41** — `SuggestPersona(cards, pkgID)`：只看能指派的卡（`live`、沒被蓋住、`unassignable` 空）；①這個套件自己帶的（沒坐位置的優先）②沒坐位置的第一位 ③其他第一位；跟看板 `suggestPersona`（WEB-63）同一套。
- **PKG-42** — 同一個職位只問一次：狀態存 `settings/packages.toml` 的 `[claims.<職位 id>]`（沒認領過的家檔案不變）；已有紀錄就不發，回 `sent = false` 與當時的 `state`、`notice`、`detail`。

## NEVER
- **PKG-N1** — 不在核心裡呼叫 AI：差異清單只產生檔案，整理與詢問是秘書的事。
- **PKG-N2** — 不改官方與分享層的資料夾；fork、安裝只寫 `packages/mine/`、`packages/installed/`，解除安裝不刪 `packages/mine/`。
- **PKG-N3** — 不重複監督別人在監督的套件行程（引擎套件由引擎模組啟動與握手，這裡只列狀態）。
- **PKG-N4** — 不出現平台專有名詞、不依套件名稱分支（D-21、MOD-N3）。
- **PKG-N5** — 沒有主人同意不裝任何東西：`InstallGo` 沒有 `confirmed` 一律 `INVALID`；編譯失敗、`GoStatus` 都不自己去下載 Go；不用 Homebrew、不用 `sudo`、不改 PATH 或 shell 設定（PKG-65）。套件 `go.mod` 寫的外部模組是套件的一部分（裝、寫這個套件時就決定了），編譯時從公開的模組站抓不算「裝東西」（PKG-66）。
- **PKG-N6** — 沒有 `confirmed` 不從網址安裝；帳號密碼不進 `.source.toml` 或 log；網址安裝的暫存只放 `.install-*`／`.upgrade-*`／`.preview-*`（掃描略過），結束都刪。
- **PKG-N7** — `New` 只寫 `packages/mine/`：先寫隱藏的 `.new-*`、驗過才 rename，失敗什麼都不留；不動其他層與別的套件、不覆蓋、不寫 `vault/pkg/<id>/`。
- **PKG-N8** — `Export` 不改套件資料夾、不寫 `vault/`、`packages/`；不跟符號連結；不把疑似金鑰完整寫進回應或 log；不替使用者 `git init`／`push`；掃到個資不自動改檔、不默默略過。
- **PKG-N9** — 認領不是通用的「秘書指定動作、主人一鍵執行」：只有認領職位這一種、參數由核心在發通知時決定；秘書的回答、自動回答、別的通知一律不動作；`Sync` 的 `apply` 仍只有主人。
- **DAT-N1** — `packages/data` 不自己存取檔案（一律經 vault）；不替核心種類開寫入。

## 職責
- 探索與載入、附程式套件的編譯／啟動／`Hello`／重啟／`InstallGo`、改動偵測、擴充點、fork 與更新差異、找 Go 與下載 Go（PKG-65）、使用者套件的鷹架（資料夾地圖在 `conventions/user-features.md`）、跟著程式的說明文件 `evergenie docs`（PKG-67）、匯出與個資掃描、預覽、網址安裝與升級、認領通知。

### 行為細節
- 位置：官方＝`SetOfficialDir` ＞ `EVERGENIE_OFFICIAL_PACKAGES_DIR` ＞ `<家>/packages/official` ＞ 執行檔旁（`platform.ExecutableDirs()` 的每個資料夾各試 `../packages/official`、`packages/official`，經過符號連結的也找得到，PLT-24）；分享＝`packages/installed/`；自己的＝`packages/mine/`；隱藏資料夾略過。`installed` 跟官方同 id 時 `installed` 被拒。manifest 不合格（`schemas/package.md`；另外 `id` 跟資料夾不同、指的檔不存在、`[fork]` 在 `mine` 以外）→ `INVALID`（帶 `field`）、`rejected`；相依問題往上傳（`version.go`）。
- 監督（`supervise.go`、`build.go`）：第一拍編譯（官方先找發版附的執行檔：`EVERGENIE_PACKAGE_BIN_DIR` ＞ `EVERGENIE_ENGINE_BIN_DIR` ＞ 執行檔旁，PLT-24）後啟動，環境 `EVERGENIE_HOME`、`EVERGENIE_API_SOCKET`、`EVERGENIE_PACKAGE_*`、跟著程式的公開卡資料夾 `EVERGENIE_BUNDLED_PERSONAS`（官方套件資料夾的 `personas/cards/`，外面帶進來的同名變數換掉；agents 的 PRS-25，測試 `TestPackageEnvBundledPersonas`）；15 秒內沒 `Hello` 算失敗。狀態 `building`→`running`／`failed`／`stopped`／`rejected`；純資料載入就是 `running`；停用不通知。重啟 `always`（預設）／`on-failure`／`never`，退避 5 秒起加倍、上限 5 分鐘，跑滿 60 秒歸零，連續 5 次停手；`system.alert` 同套件 10 分鐘一次（LOG-6）。指紋（路徑、大小、修改時間）連續兩拍一樣才算改完；舊行程跑到新版編好才換；`build.stamp` 沒變不重編。編譯中重掃（偵測到存檔、`Reload`）換了一份 entry 時，編完的結果算在現在這份上（`buildID` 對得上；不然會一直停在編譯中）；編譯中又要求重編的，編完再編一次（`TestRescanDuringBuild`）。編完時套件已經不歸監督管（編譯中停用、manifest 改壞、被拒）就不啟動、不通知、狀態不停在編譯中（`TestBuildDoneButNoLongerRunnable`）；跑著的套件後來被拒（manifest 壞了、相依的套件停用、資料轉換沒過），下一拍把行程收掉（`TestRejectedWhileRunningStops`）。
- `InstallGo`：已有能用的 Go 不下載；下載沒成功、裝完還是用不了 `UNAVAILABLE`（白話，PKG-65）；原始碼版、沒有這台晶片的包、下載設定讀不到 `CONFLICT`（重試也一樣）；同時一個（`CONFLICT`）；秘書回合能不能跑照 D-24（`go-status` 算唯讀，`install-go` 算寫）。
- `Hello` 只接受核心剛啟動、還沒報到的那個，`api`、`version` 要跟 manifest 一樣；回 `token`、`data_dir`、`granted`。`Install` 本機資料夾（`tier` 預設 `installed`，`official` `FORBIDDEN`）先驗、暫存再 rename；`Uninstall` 只移除 `installed`；`SetEnabled` 停用的收掉、依賴它的被拒。
- 擴充點：`values` 是 `<套件>.<擴充點>` → 字串，`SetExtension` 空 map＝拿掉。fork（`fork.go`，對外入口已關、PKG-5；模組方法留給舊複製品與測試）：只 fork 有效的官方，整包複製＋`.fork-base/`＋尾端 `[fork]`。`ListUpdates`（`updates.go`）逐檔比 `.fork-base/` 與現在的官方，寫 `runtime/packages/<id>/updates/<基準>-to-<新版>.md`。
- 資料種類規格檔、職位樣板 `agents/<id>/agent.md` 的格式見 `schemas/package.md`；資料寫入走 vault、**不轉給套件行程**；排程樣板格式同 `schemas/job.md`，`Sync` 時才解析。
- `Sync`（`sync.go`）預演：秘書 create／update／same、排程 create／exists。套用：非主人 `FORBIDDEN`（先於一切）；樣板先全部驗完；封存過的 id 不能重用（`CONFLICT`）；create 建停用的新秘書再寫官方職責（`by: system`），排程 `source`＝套件 id；中途失敗不回滾（再同步一次當 same／exists）。

### 核心頁面留給套件的 slot（`[[contributes.page]] slot = "<id>"`）
核心只留位置、不知道誰會掛（法律第 3 條）；掛的頁面由核心 esbuild 編譯，各包一層 PackageBoundary（一個壞了不影響別的），套件關掉就消失；宣告了 `show_when` 的，條件不成立也不列（PKG-69、MNU-11：例「API 支援才顯示」的分頁寫 `show_when = "cap:<套件>.<能力>"`）。排序：`slot_front = true` 在前，其他依頁面 id（`<套件>.<頁面>`）。頁面清單由 `menu` 的 `GetPages` 給（MNU-3），看板用 `pkg/Slot.tsx`。

有哪些位置、各自多給元件什麼 props、怎麼顯示：正本在 `conventions/user-features.md`「頁面怎麼寫」第 5 點（跟著發行檔帶給主人那台的秘書，DEV-155）；加位置、改 props 時改那張表（RMD-25、WEB-163、WEB-164 是各位置的實作）。

每個元件另外照舊拿到 `pkg`、`page`、`search`（`window.location.search`）。要換頁用 `@evergenie/host` 的 `navigate(href, {replace?})`（走看板路由，WEB-165），不要 `window.location`。

### 套件怎麼掛角色分頁（給角色工坊這類套件，DEV-143）
一位角色一頁的分頁是給「跟一位角色有關、但不是角色卡本身」的東西：衣服（closet-mine 的「衣服」）、聲音、照片集、角色工坊的設計稿…。做法：

1. `package.toml` 宣告一個頁面掛 `core.persona.tab`，`title` 就是分頁名（短、兩三個字；寫給主人看的名字，照 `conventions/terms.md`）。不用寫 `route`：掛在 slot 的頁面只能從角色頁打開，看板不給它自己的網址（`/p/<套件>/<頁面>` 會顯示找不到；`menu/pages.go` 只幫沒有 slot 的頁面組網址，PKG-45 的 `route` 本來就保留未用）。
2. 元件的 props 讀 `persona`（核心一定會給）。不要自己畫角色的頭像、名字——角色頁上面核心已經畫了。分頁裡有「總覽 → 點開某一項」的畫面時，打開哪一項不要只放在元件的 state：用核心給的 `item`（網址 `?item=` 的值）與 `onItem(id)`（空字串＝回總覽），重新整理才會回到同一個畫面（closet-mine 的「衣服」分頁就是這樣）。
3. 只做這位角色的事；要連回自己的別的頁面用 `<a href>`（看板會接成站內換頁）或 `navigate`。
4. 也想讓主人從「新增角色」用你的方式建角色，另掛一個頁面在 `core.personas.new`，建好呼叫 `onDone(新角色的代號)`。

```toml
# packages/mine/studio/package.toml（例：角色工坊）
[[contributes.page]]
id = "design"
title = "設計稿"
component = "pages/design.tsx"
slot = "core.persona.tab"
# slot_front = true   # 想排在別的套件分頁前面才寫

[[contributes.page]]
id = "new-from-sketch"
title = "從草圖建"
component = "pages/new-from-sketch.tsx"
slot = "core.personas.new"
```

```tsx
// pages/design.tsx
export default function Design({ persona = "" }: { persona?: string }) {
  return <section data-testid="studio-design">{/* 這位角色（persona）的設計稿 */}</section>;
}

// pages/new-from-sketch.tsx
export default function NewFromSketch({ onDone, onCancel }: { onDone?: (slug?: string) => void; onCancel?: () => void }) {
  // 建好後：onDone?.("mysketch1")；取消：onCancel?.()
  return null;
}
```
分頁出現在 `/personas/<代號>?tab=studio.design`；套件關掉後那個網址回到「介紹」。

## 事件
- 發出：`system.alert`（`{title, context, agent: ""}`：套件掛了、停手、編不過、無法啟動、需要 Go、認領沒設好）。
- 訂閱：`notice.answered`（只處理 `source = package` 的認領，PKG-43）。`packages/data` 無（`watch` 只把 vault 的變更轉成串流）。

## 儲存
- `settings/packages.toml`（`[enabled]`、`[extensions]`、`[claims.<職位 id>]`）：經 `platform.LoadPackageSettings`／`SavePackageSettings` 原子寫；檔案壞掉時讀當沒設定、寫入拒絕。
- `packages/installed/`、`packages/mine/`；`runtime/packages/<id>/`：`bin/`、`build.stamp`、`out.log`（每次啟動一行「---- 時間 啟動 執行檔」，超過 1MB 留最後 256KB）、`updates/*.md`、`public/`（套件行程寫，看板 `/pkg-files/<id>/` 唯讀送出，D-29、PKC-10）；`runtime/exports/`（可刪、不備份）；`runtime/backups/packages/`。套件資料 `vault/pkg/<id>/`。

## 依賴
`vault`、`platform`、`app`（登記介面與 `cmdline`）、`base/agent/personaref`（人設卡解析）、`engine`（健檢只用 `engine.Status` 型別）；同塊的 `packages/pkg`、`packages/data` 不算依賴。名冊、匯流排、引擎監督、同步要的名冊與排程、認領要的角色庫與通知都不 import：在 `Deps` 與 `Set…` 定義小 interface，由組裝接上。

## 錯誤
各條 MUST 寫明回什麼。大類：`INVALID`（輸入或 manifest 不合格、沒 `confirmed`、沒帶 `by`）、`NOT_FOUND`（套件、擴充點、職位不在）、`CONFLICT`（同名已存在、狀態不對、升級失敗已換回、`expected_revision` 不符、這份程式不能幫忙下載 Go）、`FORBIDDEN`（動官方層、匯出官方或 fork、非主人 `apply`、寫核心種類）、`UNAVAILABLE`（沒有 git、下載 Go 沒成功、抓不到網址、還沒有家、讀寫失敗、沒接 `SyncHost`／`ClaimHost`／vault）。

## 不變條件
- 上面每條 MUST／NEVER 都是不變條件；另外：
- 套件比核心的 API socket 晚 0.5 秒起來照樣報到；一直連不上 10 秒內回錯誤；重開後 `out.log` 還有上一次的輸出。
- `New` 建出來的套件載入成 `running`／`mine`、鷹架不含家的路徑、看板有頁面與選單；保留字涵蓋核心看板每個路由第一段；`conventions/user-features.md` 的保留字、「給秘書」、分享各節跟程式一致。
- `--git` 匯出的資料夾 git init＋tag 後，別的家用 `file://` 裝得起來、角色庫馬上有 `<id>.<slug>`、沒有原主人的資料。
- 使用者的套件不拖累別人（真 serve 驗）：壞的只有它被拒、一直掛只發 `system.alert`、升級與重開不動 `packages/mine/`、`personas/mine/`、`vault/pkg/<id>/`、移除後秘書起得來。
- 被擋的資料寫入不到 vault。

## 設計決定
- **D-27** — 套件的資料統一放 `vault/pkg/<套件 id>/`（`Hello` 回的 `data_dir`），解除安裝不刪。附程式的套件需要 Go、電腦沒有時：不自動裝，也不丟一行指令給主人——套件標 `failed`＋白話原因（能幫忙下載時帶補救代號 `install_go`）並通知；秘書在對話裡說明，主人同意後才呼叫 `PackageAPI.InstallGo`（`confirmed = true`），由核心把寫死的那一版 Go 從官方下載點下載到程式自己的資料夾（`<app>/tools/go`，對過 sha256；DEV-155 起，之前是 `brew install go`，PKG-65）；原始碼版（開發機）不下載，要自己裝。

## 已知限制
- `Hello` 發的 token 還沒有被檢查（D-19 只是邊界）。
- 附程式的套件升級後在背景編譯，編不過顯示 `failed`、不自動換回（只在重掃就被拒或立刻 `failed` 時換回）。
- 個資掃描是樣式比對（寧可多報）：沒前綴、亂度不高的密碼掃不到；圖片、壓縮檔內容不看。看板沒有「匯出」按鈕。
- 網址裝的套件沒有簽章：預覽標「會在你的電腦上執行程式」，裝不裝由主人決定。
- 下載 Go（PKG-65）：寫死的版本跟發版一起手動更新，沒有自動提醒；只有 https 與 sha256，沒有驗 Go 官方的簽章。找 Go 時不看 `/usr/local/go/bin`（官方安裝程式的位置，launchd 的 PATH 沒有它）：下載版只看工具資料夾與 PATH，用官方安裝程式裝了 Go 的主人還是會被問一次要不要下載。同一個程式資料夾配兩個家、同時按下載會互相蓋。秘書主動提議裝 Go 只靠白話錯誤、`remedy`、`go-status` 與技能 create-feature。
- 編主人的附程式套件（PKG-66）：`go mod tidy`、在工作區外面跑的 `go get` 不認附的 sdk（會去網路找、找不到）；要用外部模組只能手寫 `require`。套件自己的程式寫錯是一句白話＋go 的英文原文（給秘書修），套件的錯誤欄位只有一個，所以看板的套件列也看得到原文；給主人的通知只有白話。外部模組網路不通的白話只用 go 的輸出樣本驗過（`TestBuildFailurePlain`），沒有真的斷網跑過。下載的 Go 第一次用會在 `~/Library/Application Support/go` 寫它自己的使用統計設定（只在本機、很小，Go 1.23 起；移除時選做，`runbooks/install.md`）。編不過的套件在編譯中又被 `Reload`（或存檔），編完會再編一次，主人可能收到兩則一樣的「編譯失敗」通知（照「編完再編一次」的設計，沒有去重）。sdk 改了不相容的地方，主人已經寫好的套件升級後會編不過（白話「對不上」，舊的執行檔照跑），要秘書照新的 sdk 改。
- 合併 fork 之後沒有「更新基準」的動作，合完 `ListUpdates` 仍列同樣項目；fork 的 Go 套件 `go.mod` 裡 sdk 以外的相對路徑 `replace`，複製後可能編不過（sdk 的由工作區蓋過，PKG-66）。
- 引擎套件由引擎模組依內建清單啟動；`Reload`／停用不會重啟引擎。
- 套件的資料轉換只有四種宣告式動作，要算的（拆欄位、合併紀錄）做不到。轉換前留的原檔備份（`<種類>.bak-<日期>-migrate-<id>/`）沒有自動清，照備份的規矩由人或秘書收。別人分享的套件新版可以帶 `remove`：主人的欄位會被拿掉（原檔在備份裡），`packages preview` 還不會特別標出來。
- `prompt_append` 的值改了之後，已經開著的對話不會重讀，下次開對話才帶進去；`until_record` 的紀錄寫進去之後也一樣，已經開著的對話還帶著那段，要靠內容自己擋第二次（例：習慣的第一次介紹要秘書先寫紀錄、寫成功才講，HAB-21）。
- `[[contributes.page]] merge` 只收宣告，看板還不照它合併各台（`TestManifestPageMergeDeclaration`）。
- 改動偵測是每 2 秒輪詢，很大的 `mine` 套件每拍要走一次資料夾。
- 認領：主人封存還沒回答的通知時紀錄停在 `asked`、不再問；秘書經 API 冒用 `owner(…)` 擋不住（D-24）；主人按「好」之後不另外傳話給請的秘書。

# 模組：agents（`internal/feature/agents`）
Status: DRAFT — 2026-11-02 S8-3 合併 agents.md、personas.md，pending author review.

**目的：** 秘書與角色：名冊管理（新增、封存、改名、換角色、換帳號、改欄位、附加規則、寫入各帳號的秘書檔）、秘書自己的記憶與日誌的寫入、看板的名冊（roster）；角色庫（人設卡的列出、新增、複製、編輯、檢查、上線／設計中、說話層強度、套件角色）與角色包（persona）。名冊資料的讀寫與組裝 session 指令在底層 `agent`。
**種類：** 業務塊（7 塊之一；子套件 `agents/roster`〔原 `agents`〕、`agents/notes`〔主題筆記，DEV-161〕、`agents/persona`〔原 `personas`，含 `persona/personapack`、`persona/personaexport`、離線改代號的 `persona/recode`〕；另有官方純資料套件 `packages/official/personas`；法律第 8 條）

### agents/persona
- **PRS-1** — （D-31 改寫）角色庫管理（列出、新增、編輯、上線、移回設計中、說話層強度 A–D、套件角色）在本子套件（`library.go`、`styles.go`、`package.go`），規則寫在底層 agent 卡的 AGT-20、21、23、31、32；官方套件 `personas` 不做這些。名冊讀角色經 `source.go` 的 `Card`、`Style`（組裝用 `agent.SetPersonaSource` 接給名冊）。
- **PRS-2** — 角色包：使用者升級後下載同版號的包；沒網路也不退版。

## 不變條件
- 上面每條 MUST／NEVER 都是不變條件；另外：
- `Create` 沒給職責時，職位 id 是啟用中套件帶來的職位（`Deps.Templates`）就用樣板的一句話職責，否則記「（還沒寫）」（`TestAgentsCreateUsesTemplateDuty`）；拒絕壞格式與已存在的 id、秘書身分、不存在的人設；`Archive` 之後資料還在、同 id 不能重建。
- `Rename` 之後記憶、附加規則跟著新 id、舊 id 不在名冊；新 id 已被用 `conflict`；搬排程失敗時名冊資料全部搬回舊 id。
- `Swap` 兩位同一個角色時報錯且兩筆都不動；`Assign` 到同一個或不存在的角色報錯。
- `SetField` 對白名單以外（`persona`、`id`、`former_names`、`account`…）回 `invalid`，布林與顏色寫錯 `invalid`，空字串拿掉選填欄位。
- `AddRule` 之後執行官方職責更新，附加規則的內容與版本不變；別的秘書加規則被拒絕。
- 沒帶 `by` 的寫入一定被擋下、名冊不會被呼叫；`link` 沒 `apply` 時引擎的寫入旗標一定是 false，秘書送 `apply` 回 `forbidden`、引擎沒被叫到。
- 指令表跟其他業務塊不重名（同名在 `featureCommands()` 合併時被擋）。
- 隱藏版不進角色包；同步全有或全無。

## 設計決定
- **D-63** — 角色匯出／匯入（DEV-116，作者 2026-11-04「角色跟衣服要綁一起」「不是互傳檔案, 是 export & import」；計畫 `2026-11-04-persona-export` 的 D-A～D-F）：主人在自己的家把點名的角色匯出成一個檔（`.hgpersona`＝zip：`manifest.json`＋`files/<邏輯路徑>`），對方的主人在他的家匯入；家與家不連線（法律第 7 條）。一位角色＝角色卡＋她的圖（含全身照、使用者自己加的衣服的圖）＋衣櫃資料夾＋目錄卡＋**套件宣告要跟著走的紀錄**（PKG-57：closet 的 `outfit` 跟著角色欄位、`variant` 跟著資料夾裡她的圖），核心只看 manifest 的宣告、不認得 closet（法律第 3 條）。這是主人私下給的，所以不看 `public_personas`、不套角色包的內容過濾；製作用的設定（`wardrobe/<代號>.toml`、`src/`、`*.locked.*`）照樣不收。匯入只新增與替換、不刪；本機有而內容不同的不蓋（上一次匯入寫的、之後沒改過的才換），`--force` 才蓋並先備份；全部先驗再寫。宣告只給 `given` 的種類：核心發編號的種類到別的家會撞號。兌換紀錄不跟：只有 closet 程式能寫，對方照 `cost` 自己兌換。否決：①家與家直接傳（違反第 7 條）；②匯出整個 `personas/` 資料夾（會帶到別的角色與製作用的檔）；③核心寫死 closet 的種類與欄位（違反第 3 條）；④匯入時把卡改成設計中（要改檔案內容，sha256 就對不上、也分不出之後是誰改的；卡照原樣，狀態照角色庫的規則讀）。追加（2026-11-04，code 定）：套件可以再宣告 `export_omit`（PKG-58），把只屬於這個家當下狀態的欄位（衣櫃隱藏版的開關 `on`）留在原本的家：匯出與角色包不帶，匯入時本機已有就保留本機的值；開關跟著走會讓對方的家一匯入就被打開或關掉。官方角色包也帶同一份宣告的公開角色紀錄（計畫 D-E、S4，PRS-14～16），但只帶 `by_persona` 的（衣服目錄）；`by_folder` 的（隱藏版這類使用者自己定義的圖組）連同圖只走主人點名的匯出，不進公開的角色包（2026-11-04 code 定）。同步照匯入的規則寫，收、驗、比對、寫入跟匯出匯入共用 `personapack/records.go`，不另寫一份。
- **D-65** — 程式帶的公開卡排在主人的卡後面（PRS-27，DEV-155 S7 審查 2026-11-13）：舊家有不是 `my_` 開頭、跟新加的公開角色同代號的我的卡時，換版不能悄悄換掉主人用的那位（坐她的秘書、記在她名下的紀錄）；官方角色資料夾的卡不改（現有家的行為不變）。被蓋過的那張不列、不標 `Shadowed`：`Shadowed` 一直只表示「我的卡被官方資料夾同代號的卡蓋住」（看板標「被官方蓋住」、指令找角色與認領略過它），反方向沿用會把官方卡標成被官方蓋住；被蓋過的那張本來就指派不到、`show` 不到，列出來只會多一張點不進去的卡。匯入照同一條算「這個家現在用的是哪一位」（PRS-9）：程式帶的那位在用＝匯入同代號的「我的」照舊擋；已經是主人的那張＝同一個位置。只提醒、不自動改（doctor，升級報告也收它的黃字給電腦秘書），因為改代號要連名冊、圖與紀錄一起改。

## 已知限制
- 新家第一位秘書的招呼（AGS-11）只在「建的時候名冊是空的」那一位記：新家先請了一位又在她還沒啟用前封存，再請的那位不會收到招呼（名冊有過人）；空的家用 `packages sync --apply` 沒指定職位、一次建好幾位停用的秘書時，只有第一位記 `first_day`，主人先啟用別位就沒有招呼。第一次啟用時佇列寫不進去、或她那時 mode 是 `none`，就不會有招呼（不補送，免得送出過期的「第一天」）；主人自己先開口照常聊。招呼排進佇列之後的補送全靠佇列與 session 的派送（還沒結束的封包不會被清掉），核心不另外重排。
- 新角色的招呼（PRS-13）署名是 `system`：家裡剛好有一位 id 叫 `system` 的秘書時，訊息頁照秘書篩選會把它算在她底下、主人對 `system` 設的「關閉」也會套到這則；寄件人名字與頭像已由 `speaker`／`image` 換成角色本人。通知送出成功、寫回清單失敗（磁碟滿）的極小窗口下一輪會重送一次。同代號的「我的卡」（蓋掉官方卡）不擋招呼，招呼內容照官方卡。
- 官方角色包排除「沒帶的紀錄的圖」（PRS-29）只認得照命名的檔：`<代號>@<其他>…` 與 `wardrobe/<代號>/<其他>/`。認不出來的照樣進包：①放在官方位置、**完全沒有紀錄**的圖（核心不知道它是哪套衣服，照檔名收）；②每位角色的第一套 `<代號>-base` 的圖檔名是 `<代號>.<副檔名>`，沒有 `@base`，那筆紀錄被擋下時圖照收（主人把 base 標成 `private`，PKG-71，也一樣）；③`wardrobe/<代號>/` 底下不照 `<其他>/` 分資料夾、檔名也不照命名的檔；④沒宣告 `persona_id = "prefix"` 的種類；⑤`--no-records` 而這個家沒有照紀錄帶圖的種類（不讀紀錄，不知道哪些被擋；有照紀錄帶圖的種類時照樣讀紀錄，連不到服務不建，PRS-4）。現在的做法：新衣服一律先在 `personas/mine/` 做（那裡的檔一律不收），升成官方才搬到官方位置；建包的輸出列出每個收進來的子資料夾與沒帶的編號，發行前照發版手冊「角色包」對一下。包裡的目錄卡 `catalog/<代號>.md` 是手寫的檔、照原樣收，裡面寫了什麼核心不看。
- 照紀錄帶圖時「檔名是別的角色的不帶」（PRS-30，DEV-160 審查）只認得這個家知道的角色（官方或自己的卡、程式帶的卡、有紀錄的代號）：檔名是一個這個家沒有的代號、又被公開角色的紀錄指著的圖照樣帶（例 `avatars/pack/renamed.png` 這種改過名的舊圖本來就要能帶）。名字是隱藏版的規則對紀錄檔只看資料夾、不看檔名本身（檔名沒有意思，DEV-160）；只靠檔名標成隱藏版、卻被一般紀錄指著的檔會帶。
- 沒宣告 `pack_only` 的 `by_persona` 種類，公開角色的每一筆都進官方角色包（PKG-59 起就是這樣）：新的種類要不要公開，由宣告的套件自己寫條件；這個家的官方衣櫃若被沒有 `pack_only` 的同名套件蓋掉，建包不會提醒。
- 已經同步進別人家的紀錄不會因為新版的包不帶了而刪掉（同步只新增與替換，PRS-21）；`pack_only` 上線前建的包若已經發出去，要另外處理（現在 `pack.toml` 的 `url` 空，還沒有發出去的包）。
- 角色包還沒有公開的下載位置：`pack.toml` 的 `url` 留空，測試用 `file://` 與本機 http。
- 跟著程式的公開卡（PRS-25）：引擎行程（`EVERGENIE_BUNDLED_PERSONAS` 只帶給套件，引擎監督與背景 serve 把外面帶進來的也拿掉：`TestEnvironmentCarriesLayout`、`TestProcessEnvDropsLayout`）與舊核心開的套件行程沒有這個變數，只看官方角色資料夾；現在引擎與 session 都不直接讀卡（卡由核心的角色庫注入指令），之後要讀就經 `sdk.OfficialCardPath` 並由引擎監督帶上這個變數。

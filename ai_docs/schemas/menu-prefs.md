# Schema：menu-prefs（選單偏好）

Status: DRAFT — 設計 2026-10-23（P0-S5；同日依作者的要求改成「使用者自己組的樹」），pending author review. 共通規則見 `README.md`。

選單由伺服器依「已安裝＋已啟用＋有權限」算出**可用項目**，再套上使用者自己組的樹；前端拿到才畫，不先畫再收（D-11、REQ-105；選單等太久或讀不到時看板先用基本選單，WEB-175）。這個檔只存**使用者的選擇**：樹怎麼組、用哪個呈現元件。

## 路徑
- `settings/menu.toml`（家的根目錄下）；沒有這個檔就用核心提供的預設樹。

## 欄位
TOML；`schema = 1`：

| 區段.欄位 | 型別 | 必填 | 預設 | 說明 |
|---|---|---|---|---|
| `schema` | int | 是 | `1` | |
| `renderer` | string | 否 | `""` | 空＝用預設呈現元件；否則是自訂呈現元件的 id（`<套件 id>.<元件 id>`，放在 `packages/mine/`，見 `modules/board.md` 的 WEB-15 與 `modules/inbox.md` 的 MNU-4） |
| `hidden` | list of string | 否 | `["core.policy"]` | 收到設定的項目 id（MNU-10）：不出現在選單，列在設定頁。空清單＝全部放回選單；`core.overview`、`core.settings` 不能收 |
| `[[entry]]` | 陣列 | 否 | 預設樹 | 頂層項目，**依順序**就是畫面順序 |
| `entry.item` | string | 與 `group` 二選一 | — | 葉：一個可用項目的 id（核心 `core.chat`、套件 `<套件 id>.<項目 id>`） |
| `entry.group` | string | 與 `item` 二選一 | — | 群組 id（自取，樹內唯一，例 `work`） |
| `entry.title` | string | 群組必填 | — | 群組名稱（使用者自己取） |
| `entry.icon` | string | 否 | — | 群組圖示 |
| `entry.children` | list of string | 群組必填 | `[]` | 群組底下的項目 id，依順序；**只能是項目，不能是群組** |

## 約束（寫入時驗證）
- **最多兩層**：頂層（項目或群組）→ 群組底下的項目。`children` 裡出現群組 id 一律拒絕（`ERROR_CODE_INVALID`，`field: entry.children`）。
- 同一個項目在樹裡只能出現一次；群組 id 不重複。
- `core.settings` 永遠可達：樹裡沒有它時，伺服器在最後補上，使用者不能移除（這是使用者弄壞選單時的退路，設定頁的選單編輯器也在裡面）。
- 項目 id 不存在（套件被移除、停用、沒權限）：**略過，不報錯**；`doctor` 列出失效項目。偏好檔保留它（套件重裝時選擇還在）。
- 沒被放進樹的可用項目，自動出現在最後一個內建群組「未分類」，所以裝了新套件之後它的頁面一定找得到。
- **同一個 `section` 的項目放在一起**（MNU-7、D-62）：畫選單時，第一次遇到某個 section 的項目，就在那個位置依可用項目的順序（核心在前、再照套件的 `order`）放下這個 section 的全部項目，包括樹裡沒寫的；後面再寫到的略過。所以存過樹的家多了新的核心項目「介紹」，會跟樹上的衣櫃、展示間合成一個「角色」入口，不進「未分類」。檔案不改寫；樹上一個同 section 的項目都沒有（例：衣櫃停用而且樹裡沒寫介紹）才進「未分類」。

## 預設樹
核心在沒有 `settings/menu.toml` 時產生：群組 `daily`（今天、聊天、待辦、manifest 宣告 `front = true` 的套件項目、訊息、任務單）、群組 `work`（Goal；權限申請預設收到設定，見 `hidden`）、各套件項目依 manifest 的 `group_hint` 接在同名群組的**最後面**（沒有就進「未分類」）、最後是 `core.settings`。帶 section 的核心項目（介紹）放在同 section 第一個套件項目的前面，沒有同 section 的套件就接在 `daily` 最後（MNU-8）。任務單放在 `daily`、套件接在它後面，是為了不讓一般套件把它們擠進手機的「更多」（官方套件的 `group_hint` 全是 `daily`；REQ-201）；手機底部列前 5 格是今天、聊天、待辦加前兩個 `front` 項目，訊息、任務單在「更多」。使用者第一次編輯選單時，才把預設樹展開寫成檔案。

## 連結
| 方向 | 欄位 | 指向 | 規則 |
|---|---|---|---|
| 出 | `entry.item`、`entry.children` | 核心頁面或套件的選單項目 | **容忍失效**（見上） |
| 出 | `renderer` | 自訂呈現元件 | 不存在或編不過 → 退回預設呈現元件，並在看板顯示一行提醒 |

## 保存規則
- 不封存、不刪除；改動留在 git 歷史。
- 失效的項目 id 保留；滿 180 天沒出現在可用項目裡，清道夫只報告、不自動刪。

## 從舊系統遷移
舊看板的分頁是寫死的（`index.html` 的 `TABS`、`HUB`、`SETS`），使用者沒有組合選單的設定。None.（上線時 `settings/menu.toml` 不存在，用預設樹。）

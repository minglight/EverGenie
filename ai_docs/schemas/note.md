# Schema：note（主題筆記、分類說明與索引）

Status: DRAFT — 2026-11-15 DEV-161 定案，pending author review. 共通規則見 `README.md`；各秘書自己的記憶核心與日誌是另外兩種資料（schema memory、journal）。

全家共用、照主題放的長期記憶：一個人、一樣東西、一個地方、一個專案一份。任何秘書和主人都能整理，每一行留名；檔名就是看得懂的名字，用 `[[名字]]` 連結，主人用 Obsidian 打開看得懂。

## 路徑
- 主題：`vault/notes/<分類>/<主題>.md`（紀錄種類 `topic`，id `<分類>/<主題>`）。檔名就是名字，中文可以。
- 分類的說明檔：`vault/notes/<分類>/<分類>.md`（種類 `topic_category`，id `<分類>`；Obsidian 的 folder note 寫法）。
- 總索引：`vault/notes/索引.md`；職位索引：`vault/agents/<職位 id>/索引.md`。核心產生，不是紀錄（見「索引」）。
- 固定主題「主人」：`vault/notes/人/主人.md`，取代退休的 `vault/profile.md`。
- 固定主題「梗本」：預設 `vault/notes/喜好/梗本.md`（見「梗本」）。
- 已封存：`vault/notes/<分類>/archive/<YYYY-MM>/<主題>.md`（照共通規則；沒有自動封存，只有 `evergenie notes archive`，見「封存」）。

種類名不叫 `note`：`note` 是秘書自己的做事筆記（`vault/agents/<職位>/notes/`，schema memory），兩個是不同的東西。

名字（主題與分類）的規則：不能空白、前後不能有空白、不能有 `/ \ : * ? " < > | [ ] # ^`（名字是檔名也是 `[[連結]]`）、不能 `.` 開頭或含 `.bak-`（核心不看這兩種）、不能叫 `索引` 或 `archive`、最多 60 個字；主題不能跟自己的分類同名；全家的主題名字不重複（`[[名字]]` 才指得到唯一一份；建新主題時檢查，手改造成的重名與跟別名撞名現在不報）。

## 主人自己放在 vault/notes/ 的檔
`vault/notes/` 底下檔頭沒有自稱是主題（`name` 欄位）或分類說明（`kind: category`）的檔（含沒有檔頭、檔頭讀不懂的），一律當主人自己的筆記：不進索引、不算壞檔、`doctor` 不報、不改；新建主題或分類遇到那個位置已經有主人的檔就回 `CONFLICT`，不蓋（預設分類也不補）。自稱主題、欄位卻壞掉的才報。

## 官方預設分類
`人`、`東西`、`地方`、`專案`、`喜好`（說明文字在 `internal/base/agent/notes.go` 的 `DefaultCategories`）。核心每次啟動補上缺的（只建缺的，已經有的、主人改過的一個字都不動；封存掉的不算缺）。秘書要加新分類，先問主人一次，再 `evergenie notes categories add <名字> --summary <放什麼>`。

每個預設分類有建議的固定段落（DEV-161，寫在新家的分類說明檔裡，`evergenie notes categories list` 會在那個分類底下多印一行）：主題內容多了以後，用 `notes set` 照這幾個 `## 標題` 整理；一開始用 `notes add` 一行一行加就好（會接在最後）。只是建議：不驗證、不強制，已經有的說明檔與筆記不動（舊家的說明檔沒有這一段，照下表）。

| 分類 | 建議段落 |
|---|---|
| 人 | 他是誰／喜好與禁忌／最近的事 |
| 東西 | 設定／上次的感想／要注意的 |
| 地方 | 怎麼去／注意的事／上次去的感想 |
| 專案 | 目標／現況／決定過的事 |
| 喜好 | 喜歡／不喜歡／糾正過的 |

## 欄位
主題（`topic`），照檔頭的順序：

| 欄位 | 型別 | 必填 | 預設 | 說明 |
|---|---|---|---|---|
| `schema` | int | 是 | `1` | |
| `name` | string | 是 | — | 名字，等於檔名 |
| `aliases` | list | 否 | `[]` | 別名（例「小美」）；`show`、`find`、索引都看 |
| `summary` | string | 是 | — | 一句說明，索引就印這一句 |
| `follow` | list | 否 | `[]` | 跟進的職位 id（要在名冊上）；照它產生各職位索引。「主人」不用寫，算全部職位跟進 |
| `links` | list | 否 | `[]` | 套件紀錄或別的主題，寫成 `"[[…]]"`；套件已經有的資料不抄，只放連結 |
| `updated_at` | datetime | 是 | — | vault 寫入時填 |
| `by` | string | 是 | — | 最後寫的人：職位 id、`owner(…)`、`system`、`migrate` |

沒有 `id`、`created_at` 欄位：路徑就是身分（vault 新建時會補 `created_at`，不算錯）。

分類說明（`topic_category`）：

| 欄位 | 型別 | 必填 | 預設 | 說明 |
|---|---|---|---|---|
| `schema` | int | 是 | `1` | |
| `kind` | enum | 是 | `category` | 只有 `category` |
| `summary` | string | 是 | — | 一句說明：這個分類放什麼 |
| `updated_at`、`by` | | 是 | — | 同上 |

分類說明的內文寫「放什麼」「誰常用」，可以加「建議段落」（見「官方預設分類」）。

## 內文
- 一行一件事，行尾標是誰、哪天寫的：`（<職位 id> MM-DD）`，主人寫的標 `（主人 MM-DD）`；例「對花生過敏（health 11-15）」。不另記變更紀錄，被整理掉的舊內容靠主人的備份找回。
- 空行、標題（`#` 開頭）、分隔線不算一件事，不用標。
- `evergenie notes add` 一律標寫的人（送進來的行尾標記會換掉，不能冒名）；`evergenie notes set` 整份取代時，秘書新寫、沒標記或標成別人的行拒絕並列出行號（原本就在的行原樣保留不算）；主人自己寫不檢查。
- `notes set` 改內文要帶 `--revision <版本>`（`notes show` 印的「版本」＝vault 紀錄的 `revision`）：沒帶拒絕（訊息說先 `notes show` 拿版本）、版本對不上拒絕（別人在你讀過之後改過，重新 show、把對方的行留著再 set），避免兩位秘書前後整理同一份時後寫的無聲蓋掉前一位的行；只改檔頭（`--summary`、`--follow`…，沒有 `--file`）不用帶。`notes add` 是追加，不用帶。
- 套件已經有的資料（例：健身器材紀錄、任務單）只放連結，筆記只記套件沒有的（偏好、說過的話、意見）。

## 索引
- 總索引 `vault/notes/索引.md`：全部主題；職位索引 `vault/agents/<職位>/索引.md`：`follow` 有這個職位的主題，加上「主人」。
- 一個主題一行：`- [[名字]]（別名：…） — 一句說明 · 跟進：<職位>… · 分類：<分類>`，照分類、名字排序，分類標題帶分類的一句說明。
- 核心照檔頭產生，決定性（檔頭沒有時間欄位，同樣的筆記產生的位元組一樣）；檔頭寫 `generated_by: evergenie` 與「核心產生，別手改」。
- 什麼時候重產：經 `evergenie notes` 寫入之後、vault 看到主題或分類變了（含主人在 Obsidian 手改）、名冊變了、核心啟動時。內容沒變的檔不寫。
- 那個位置已經有主人自己的同名檔（檔頭沒有 `generated_by: evergenie`）就不寫，`doctor` 報索引不符。
- 退回到 DEV-161 以前的版本時（還原了遷移紀錄），家的遷移的退回收尾刪掉核心產生的索引（只刪檔頭有 `generated_by: evergenie` 的），舊版不會當成壞檔；新版再啟動會重產。
- 職位改名時，主題的 `follow` 跟著換成新 id，舊位置的職位索引收掉、新位置重產；封存的職位不產生索引、不能寫、不能被列為跟進。
- 它們不是紀錄：vault 不進索引、不監看、不算壞檔（說明卡 vault 的 VLT-18）。手改會被下一次蓋掉，`doctor` 報「跟主題筆記對不上」。

## 誰能寫
任何秘書（在自己的對話裡，身分是 `$EVERGENIE_AGENT`；封存的不行）和主人都能寫，一律經 `evergenie notes`（sdk `notes` 服務 → 底層 agent → vault），不直接改檔；核心自己用 `system`。不在名冊上的名字回 `FORBIDDEN`。各自的記憶核心與日誌仍只有本人寫。

## 開場怎麼用
所有職位開場帶「主人」全文、梗本（有上限，見「梗本」）與自己的職位索引（不帶別的主題全文）；提到人或東西先看職位索引、需要才 `evergenie notes show <名字>`；找不到用 `evergenie notes find <字>` 或總索引（每位秘書開場的共用規則）。各職位的職責另有一節「聊到什麼先看什麼」：聽到哪些話題先看哪份主題筆記與套件紀錄、回答帶什麼、聊完記回哪裡；主人說「以後聊到 X 先看 Y」，秘書用 `evergenie customize add <職位> --section 聊到什麼先看什麼 <那一條>` 記在自己職位的附加規則（升級不動）。

## 梗本
全家共用的老梗（DEV-164）：主人笑過、說喜歡的句子、秘書之間的老梗。它就是一份一般的主題（同樣的檔頭、行尾標記、`notes add`／`set`／`show`），只有下面幾點不同：
- 名字固定叫「梗本」。家裡已經有名字或別名是「梗本」的主題就沿用那一份；沒有就第一次 `evergenie notes add 梗本 <一行>` 時自己建，分類預設「喜好」、一句說明有預設，`follow` 留空（跟「主人」一樣算全部職位跟進、不能封存）。
- 一行一條：`「<那句梗>」<怎麼來的>——出處：<在哪、誰說的>`，日期與寫的人核心照「內文」的規則標。秘書寫的那一行沒有「出處」兩個字就拒絕（主人自己寫不檢查）。內容多了可以用 `notes set` 把最好的幾條放在 `## 精選` 底下。
- 開場：每位秘書開場都帶「梗本」一節（放在「主人」之後），最多 8 條、1200 字：先帶標題含「精選」那一段底下的，其餘帶最新的；少帶了會寫一共幾條、怎麼看全部。`evergenie notes quips` 印出開場那一節。
- 提過的梗：秘書回頭提了一條就 `evergenie notes quips used <那條梗裡的字>`，記在 `runtime/quips-used.json`（執行期資料，不進 vault，留 30 天），之後 7 天所有人的開場都不帶它。
- 什麼時候提（一次對話最多一次、同一條一週內不重複、主人累或出事時不提、梗不改寫事實）寫在說話層，不在這份。

## 健檢
`doctor` 的 `config.notes`（黃字，報告不擋）：主題或分類的檔頭不合、放錯位置、`name` 跟檔名不一樣、分類資料夾沒有說明檔、索引跟筆記對不上、記憶核心超過上限。檔頭讀不懂或不合規格的檔，vault 本身也照共通規則當壞檔報（`data.invalid`，紅字）；兩者都不擋啟動與升級。

## 封存
`evergenie notes archive <名字> [--into <要留的主題>]`（sdk `notes.archive`）：整理重複的主題用（例「my-mini 開發家」與「my-mini開發家」）。
- 走 vault 的 `ArchiveNow`，檔案搬進 `vault/notes/<分類>/archive/<YYYY-MM>/<名字>.md`（同月同名封存第二次放 `<YYYY-MM>-2`），不刪除；封存後 `list`、`show`、`find`、兩層索引都看不到，索引立刻重產。種類沒有設自動封存規則（`ArchiveAt`）：清道夫不會碰主題。
- 「主人」主題不能封存；分類說明檔不是主題，也不能封存；名字或別名找不到、已封存的回 `NOT_FOUND`。
- `--into`：目標主題要存在（不存在回 `NOT_FOUND`、跟自己同一份回 `INVALID`）。被封存的主題內文有目標沒有的行（比內容，不比行尾標記，所以用 `notes add` 併過去、標記換成併的人也算有）就拒絕並列出行號與內容，請秘書先 `notes add <目標> <一行>` 併過去；核心不自動搬（別人的行不能代標）。
- 寫的人照 `noteWriter`（主人、`system`、名冊上的職位）。回應說封存了哪個主題、檔案現在的位置、怎麼找回（把檔案搬回原位，請主人處理；現在沒有還原指令）。

## 保存規則
- 主題與分類是正本：不自動封存、不刪除（只有 `notes archive` 明確要求的封存）。
- 索引隨時可以重產。

# 公開前檢查與匯出

Status: DRAFT — DEV-158（2026-11-24），pending author review.

要把 repo 公開（或抄一份給外面的人）之前讀這份：怎麼掃出私人的字、命中了怎麼處理、怎麼匯出一份乾淨的檔案樹。兩支腳本：`scripts/public-check.sh`（只檢查）、`scripts/export-public.sh`（抄出去再檢查）；測試是 `scripts/public-check-test.sh`。用法與結束碼看各自的 `--help`；規則與清單格式只寫在這份。

## 私人清單
- 放在 `~/.evergenie-release/blocklist.txt`（換位置用環境變數 `EVERGENIE_BLOCKLIST`）。**不放進任何 repo**：放在要掃的資料夾裡面、或是指進去的符號連結，檢查會直接拒絕。
- 一行一條，`#` 開頭是註解：
  - 預設是固定字串、不分大小寫（只有英文字母分大小寫；中文照原字比對）。
  - `re:` 開頭是正規表示式（ERE，也不分大小寫）；寫錯或會比對到空字串就是格式錯。
  - 行尾空一格以上再寫 `# 名稱`，命中時就印這個名稱，不印那個字；沒寫名稱就印「私人清單第 N 行」。名稱不要有空白（放行清單才指得到），也不能跟內建規則同名。
  - 要擋的字本身以 `#` 開頭，或中間有「空白＋`#`」，就寫成 `re:`（例 `re:#secret-tag`）。
- 例（字都是假的）：
  ```
  # 人名、地名、內部代號
  Zorblax Quindle  # 家人名字
  re:moon-?castle-[0-9]+  # 住址
  quuxbarian
  ```
- 輸出與錯誤訊息只印規則名稱或行號，不印清單裡的字；命中的地方遮掉只留頭尾，路徑裡命中的部分換成 `[名稱]`，錯誤訊息裡的檔名換成 `[私人清單]`。

## 檢查掃什麼
- `scripts/public-check.sh [--require-blocklist] [資料夾]`：資料夾預設是這個 repo。資料夾是 git 的最上層就只掃 git 追蹤的檔（含 `git add` 了還沒提交的），不是就掃全部（`.git` 除外）。
- 沒有私人清單時印「注意：沒有私人清單，只跑通用規則」照樣跑；加 `--require-blocklist` 就直接失敗。正式公開前一律要有清單。
- 每個命中一行 `檔案:行號: 規則`；檔名、圖的中繼資料、二進位檔內容的命中行號是 0，符號連結（不跟過去）指向的路徑算第 1 行。
- 內建規則：
  - `email`、`ts-net`、`users-path`（`/Users/<名字>`）。
  - `secret-token`（`sk-`、`ghp_` 這類、`xox`、AWS／Google 金鑰、JWT）、`private-key`（PRIVATE KEY 開頭）、`secret-field`（`token`、`password`、`api_key`… 後面接 32 個字以上的值）。
  - `private-ip`：10.、172.16～31.、192.168.、Tailscale 的 100.64～127 與它的 IPv6 段。
  - `image-metadata`：圖與影片帶 EXIF（會註明含不含 GPS）、XMP、影片的位置欄位、PNG 的文字段、JPEG 的註解段與 IPTC；TIFF 一律算。
  - `odd-filename`：檔名帶換行、tab 這類控制字元（內容沒掃）。
- 二進位檔：內容只找私人清單的字（不跑其他規則），最後列出路徑與大小，公開前逐一看過。
- 子模組的內容不掃（不在這個 repo 裡），會印一行注意；`.gitmodules` 與子模組的路徑有掃。

## 內建放過的寫法
文件、範例裡用這些就不會命中，不用進放行清單（程式在 `scripts/public-check.sh` 的 `real()`，改一邊要一起改）：
- 信箱：`example.com`／`.net`／`.org`（含子網域）；`.example`／`.test`／`.invalid`／`.localhost` 結尾；帳號剛好是 `noreply`、`no-reply`、`donotreply`、`do-not-reply`、`git`，而且網域是 `github.com`、`gitlab.com`、`bitbucket.org`、`anthropic.com`；像 `icon@2x.png` 這種檔名。
- `*.ts.net`：`.ts.net` 前面那一段就是 `example` 的（`board.example.ts.net`）。
- `/Users/<名字>`：`you`、`yourname`、`your-name`、`example`、`someone`、`me`、`user`、`username`、`shared`、`test`、`tester` 和單一字母。
- 密鑰：含 `xxxxxxxx`、`XXXXXXXX`、`********`、`00000000` 這類填空字的；`secret-field` 的值要同時有數字和字母才算。
- 位址：前面接數字、字母或點的不算（版本號 `v10.4.0`、`1.10.2.3`）；127.0.0.1、192.0.2.x 這類本來就不在內網段。

## 命中了怎麼處理
依序試，能用前面的就不用後面的：
1. 改成上一段的示範寫法，或直接刪掉那段。
2. 整個檔都不該公開：寫進排除清單 `ai_docs/public-exclude.txt`（只對匯出有用）。
3. 確實該留（第三方授權裡原作者的信箱、測試用的假資料）：寫進放行清單 `ai_docs/public-allow.txt`。
4. 圖片的中繼資料：用影像軟體匯出時不帶中繼資料重存，再跑一次確認；確定內容無害（例如只有色彩空間與尺寸）才進放行清單。TIFF 請換成 PNG。

## 兩份清單的格式
- 放行：`<路徑樣式>  <規則名或 *>  # 原因`；排除：`<路徑樣式>  # 原因`。原因必填，沒寫、欄數不對都是格式錯（結束碼 2）。
- 路徑樣式：`*` 比對任何字（可以跨資料夾）、`?` 一個英數字元（中文字請用 `*`）、結尾 `/` 是整個資料夾，其他照字面；比對的是相對要掃的資料夾的路徑，開頭不加 `/`。兩份共用 `scripts/lib/public-glob.awk`。
- 放行的 `*` 只放內建規則；私人清單的字要放行，就寫出那條的名稱。`odd-filename` 不能放行。用不到的放行行會提醒可以拿掉。
- 排除清單裡沒排除到任何檔的行算格式錯（多半是樣式寫錯，本來要排除的檔會流出去）。
- 兩份清單都會跟著公開：樣式寫籠統一點，不要寫出私人的名字。

## 匯出
- `scripts/export-public.sh <目的資料夾>`：把 git 追蹤的檔扣掉排除清單，抄到目的資料夾（不帶 `.git`、不帶延伸屬性，符號連結照原樣抄，子模組不抄），再自動跑 `public-check.sh --require-blocklist`。印出抄了幾個、排除了幾個。
- 目的資料夾要不存在或是空的，不能在 repo 裡面，也不要寫 `..`。抄的是工作樹現在的內容，有沒提交的改動會提醒。
- 抄失敗時不印檔名（匯出不讀私人清單，遮不了）；跑 `scripts/public-check.sh` 會列出讀不了的檔。
- 檢查沒過時抄好的檔會留著：回 repo 清乾淨，刪掉那個目的資料夾重匯。
- `--no-check` 只給測試用，這樣匯出的不能拿去公開。

## 已知限制
- 只掃現在的檔，不掃 git 歷史。要連歷史一起公開，得另外處理歷史；匯出的檔案樹沒有 `.git`，就沒有這個問題。
- UTF-16 這類不是 UTF-8 的文字檔會被當成二進位檔，裡面的私人字找不到；在二進位檔清單裡看到就打開確認。
- 中繼資料只認得常見的標記字串，隨機的位元組剛好出現 `Exif` 也會命中；這時確認後寫進放行清單。
- 私人清單如果放在別的 git repo 裡被追蹤，檢查不會發現；請放在任何 repo 外面。
- 掃整個 repo 大約 10～15 秒。
